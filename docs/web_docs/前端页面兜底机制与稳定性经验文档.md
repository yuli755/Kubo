# 前端页面兜底机制与稳定性经验文档

> 适用范围：任何前端项目，包括 Vue、React、Angular、Svelte、Next.js、Nuxt、移动端 H5、小程序、Electron、管理后台、官网、可视化大屏和组件库。
> 文档定位：长期维护的前端兜底机制知识库。遇到新的降级、恢复、隔离、容错、补偿、监控、回滚机制，都可以继续追加。
> 使用目标：给开发者和 AI 提供“遇到同类问题时如何判断、如何兜底、如何恢复”的思路；具体编码细节另见《AI开发前必读开发技术细节规范》。
> 控制原则：保持 500-700 行左右，宁可条目化，也不要堆长篇解释。
> 配套文档：编码规范、目录结构、表单、权限、组件、测试和交付要求，见《资深前端编码前必读开发规范》。

## 0. 使用方式

建议按这个顺序使用本文：

1. 开发新页面前，先看第 1-3 节，确认错误类型和分层模型。
2. 涉及接口、表单、路由、缓存、上传、支付、审批、实时通信时，查看对应机制章节。
3. 设计高风险流程前，先看第 11、12、19、24 节。
4. 上线前，执行第 29 节稳定性测试清单。
5. 线上事故后，按第 28 节模板复盘，并把新增机制补充回本文。

本文的目标不是让所有项目实现所有机制，而是帮助你按业务风险选择合适的兜底策略。

## 0.2 最低必做清单

任何正式前端项目，至少要做到：

- 请求统一封装。
- 页面有 loading、empty、error 状态。
- 表单有前端校验。
- 提交按钮防重复点击。
- 401、403、404、500 有明确处理。
- 危险操作有二次确认。
- 全局错误有兜底提示。
- 路由不存在时有 404。
- 生产环境不暴露错误堆栈。
- 错误至少能在控制台或监控中定位。

中高风险项目还必须评估：

- 幂等键。
- 提交结果未知确认。
- 本地草稿。
- 权限降级。
- 监控告警。
- 功能开关。
- 快速回滚。

## 0.3 不要过度设计

兜底机制不是越多越好。

- 低风险页面不需要支付级别的确认机制。
- 小型项目不一定需要完整监控平台。
- 展示型页面不一定需要复杂状态管理。
- 非核心统计失败，不应该阻塞主流程。
- 强兜底应优先用于钱、权限、审批、删除、上传、长表单等高风险场景。

原则：按业务风险、用户损失、恢复成本选择机制。

## 0.4 给 AI 或开发者的使用提示

遇到前端报错、白屏、接口失败、权限异常、重复提交、弱网、上传失败、缓存污染等问题时，先不要急着改代码。按下面顺序判断：

1. 错误发生在哪一层：输入、请求、组件、页面、路由、全局、发布、第三方？
2. 错误是否会扩散：只影响一个组件，还是会导致页面或整个应用不可用？
3. 用户是否还能恢复：重试、刷新、返回、重新登录、重新提交是否可行？
4. 是否涉及高风险数据：钱、权限、审批、删除、上传、发布、长表单？
5. 是否需要记录和监控：开发者能否定位错误来源？

推荐提示词：

```text
请基于《前端页面兜底机制与稳定性经验文档》分析这个问题。
先判断错误层级、影响范围、用户恢复路径、业务风险和监控定位方式，再给出兜底方案。
不要只修表面报错，要说明如何防止同类问题再次影响其他页面或主流程。
```

## 1. 核心目标

前端稳定性不是“永远不报错”，而是：

```text
错误可以发生，但不能无限扩散。
页面可以失败，但应用不能整体白屏。
操作可以失败，但用户必须知道下一步能做什么。
开发者必须能定位错误来源。
```

成熟前端项目必须做到：

- 单个组件报错，不拖垮整个页面。
- 单个页面报错，不影响其他页面。
- 单个接口失败，不影响其他接口。
- 单个资源失败，有降级页面或默认资源。
- 登录态异常时，能清理状态并回到登录页。
- 权限异常时，默认收紧权限，不展示敏感入口。
- 用户始终有恢复路径：重试、刷新、返回首页、重新登录。
- 开发环境能定位错误，生产环境不暴露技术细节。

## 2. 前端常见错误类型

| 类型 | 典型原因 | 兜底方向 |
|------|----------|----------|
| 渲染错误 | 空对象取深层字段、组件 props 异常 | Error Boundary、默认值 |
| 异步错误 | Promise 未 catch、接口失败 | 请求封装、unhandledrejection |
| 路由错误 | 动态路由丢失、懒加载失败 | 路由恢复、fallback 页面 |
| 资源错误 | JS/CSS/图片/CDN 失败 | 默认资源、备用域名、版本刷新 |
| 状态错误 | 登录态、权限、缓存不一致 | 状态重建、安全模式 |
| 业务错误 | 重复提交、状态非法、无权限 | 校验、幂等、后端兜底 |
| 环境错误 | 低端设备、弱网、浏览器不兼容 | 能力检测、降级策略 |

## 3. 稳定性分层模型

推荐按层处理，不要把所有错误都丢给全局兜底：

```text
用户输入层
    ↓
接口请求层
    ↓
组件局部层
    ↓
页面层
    ↓
路由层
    ↓
应用全局层
    ↓
监控告警层
```

每一层只处理自己最适合处理的问题。

## 4. 用户输入层兜底

### 4.1 表单提交前拦截

必须前端校验：

- 必填
- 长度
- 格式
- 数值范围
- 金额精度
- 日期范围
- 文件大小和类型
- 跨字段关系

典型跨字段规则：

- 结束日期不能早于开始日期。
- 已付金额不能大于应付金额。
- 企业用户必须填写企业名称。
- 开票状态为已开票时，发票号不能为空。

### 4.2 防重复提交

提交动作必须有：

- 按钮 loading
- 按钮 disabled
- 请求完成后恢复状态
- 失败时保留用户输入
- 高风险操作配合幂等键

### 4.3 长表单草稿

适用场景：

- 富文本
- 审批意见
- 长表单
- 发布内容
- 多步骤表单

机制：

- 定时保存草稿。
- 页面关闭前保存草稿。
- 下次进入提示恢复。
- 提交成功后清理草稿。

## 5. 接口请求层兜底

### 5.1 统一请求封装

所有请求必须经过统一请求层，统一处理：

- baseURL
- timeout
- token/cookie
- 响应结构
- 401 登录过期
- 403 无权限
- 404 不存在
- 500 服务异常
- 超时提示
- 上传下载
- 错误信息提取

### 5.2 错误信息优先级

```text
后端业务 message
    ↓
HTTP 状态码对应文案
    ↓
网络错误文案
    ↓
默认错误文案
```

请求层可以提示错误，但不要吞错：

```js
showError(message)
throw error
```

### 5.3 请求超时

机制：

- 设置合理 timeout。
- 超时后提示用户。
- 查询接口可提供重试。
- 写接口不要盲目自动重试。

### 5.4 请求重试

适用：

- GET 查询
- 字典加载
- 非核心统计
- 临时网络波动

不适用：

- 支付
- 下单
- 审批
- 删除
- 任何非幂等写操作

### 5.5 请求去重和取消

机制：

- 相同请求未完成前不重复发送。
- 新搜索触发时取消旧搜索。
- 页面卸载时取消未完成请求。
- 防止旧响应覆盖新数据。

### 5.6 接口降级数据

非核心接口失败时：

- 统计卡片显示 `--`。
- 图表显示“加载失败”。
- 推荐列表显示空状态。
- 用户基础信息可显示匿名占位。

原则：非核心区域失败，不影响核心流程。

## 6. 组件局部兜底

### 6.1 高风险组件要隔离

建议加局部 Error Boundary 的组件：

- 富文本编辑器
- 图表
- 地图
- 文件预览
- 视频播放器
- 第三方 SDK
- 低代码渲染器
- 大型表格
- 复杂表单

### 6.2 Vue 思路

使用 `onErrorCaptured`：

```vue
<template>
  <div v-if="hasError">
    当前模块加载失败 <button @click="retry">
      重试
    </button>
  </div>
  <slot v-else />
</template>
```

### 6.3 React 思路

使用 Error Boundary：

```tsx
class ErrorBoundary extends React.Component {
  state = { hasError: false }
  static getDerivedStateFromError() {
    return { hasError: true }
  }

  componentDidCatch(error, info) {
    console.error(error, info)
  }

  render() {
    return this.state.hasError ? <div>模块加载失败</div> : this.props.children
  }
}
```

### 6.4 组件降级原则

- 图表失败，不影响表格。
- 地图失败，显示文本地址。
- 富文本失败，降级 textarea。
- 文件预览失败，提供下载。
- 第三方 SDK 失败，隐藏该模块或提供人工路径。

## 7. 页面层兜底

### 7.1 页面必须具备状态

任何数据页面至少有：

```text
loading
empty
success
error
forbidden
```

### 7.2 错误状态必须可恢复

错误页面建议提供：

- 重试
- 返回上一页
- 返回首页
- 重新登录
- 联系管理员

### 7.3 区块独立失败

复杂页面应独立加载：

- 用户信息区失败，只显示该区错误。
- 订单列表失败，不影响统计卡片。
- 图表失败，不影响详情。
- 某个 Tab 失败，不影响其他 Tab。

## 8. 路由层兜底

### 8.1 懒加载失败

路由懒加载可能失败：

- 网络异常
- CDN 异常
- 部署版本切换
- 浏览器缓存旧 chunk

安全懒加载思路：

```js
export function safeLazyLoad(loader, pageName) {
  return () =>
    loader().catch((error) => {
      reportError?.(error, { type: 'lazy-load-error', pageName })
      return { default: LazyLoadFallback }
    })
}
```

Fallback 页面应提供：

- 页面加载失败说明
- 重新加载
- 返回首页
- 开发环境错误详情

### 8.2 动态路由刷新恢复

典型问题：

```text
刷新页面
    ↓
动态路由丢失
    ↓
token/role 仍在缓存
    ↓
当前页面匹配失败
```

解决思路：

- 检查登录态。
- 检查动态路由是否已注入。
- 未注入则重新获取用户和权限。
- 重新生成路由。
- `replace` 回目标页面。

### 8.3 404 和 403 区分

- 404：页面不存在。
- 403：页面存在，但当前用户无权限。

不要所有异常都跳 404。

## 9. 应用全局兜底

### 9.1 全局错误处理

不同框架入口：

- Vue：`app.config.errorHandler`
- React：根级 Error Boundary + `window.onerror`
- Angular：`ErrorHandler`
- 浏览器：`window.onerror`
- Promise：`unhandledrejection`

职责：

- 记录错误。
- 提示用户。
- 上报监控。
- 避免白屏。

### 9.2 Promise 未捕获错误

```js
window.addEventListener('unhandledrejection', (event) => {
  console.error('[Unhandled Promise]', event.reason)
  showError('操作失败，请稍后重试')
})
```

### 9.3 资源加载错误

```js
window.addEventListener('error', (event) => {
  if (event.target !== window) {
    console.error('[Resource Error]', event.target)
  }
}, true)
```

可用于发现：

- 图片失败
- JS 失败
- CSS 失败
- 字体失败

## 10. 缓存和离线兜底

### 10.1 缓存兜底

适合缓存：

- 字典
- 菜单
- 用户偏好
- 非实时统计
- 配置信息

不适合只依赖缓存：

- 支付状态
- 库存状态
- 审批最终结果
- 权限最终判断

### 10.2 Stale While Revalidate

```text
读取缓存
    ↓
立即展示旧数据
    ↓
后台请求新数据
    ↓
成功后更新页面
```

适合提升首屏速度和弱网体验。

### 10.3 离线模式

机制：

- 监听 online/offline。
- 离线时提示用户。
- 可读页面展示缓存。
- 写操作进入待同步队列。
- 网络恢复后同步。

注意：离线写操作必须设计冲突处理。

### 10.4 浏览器存储异常

风险：

- 存储空间满。
- 隐私模式不可写。
- IndexedDB 损坏。
- JSON 解析失败。
- 旧缓存结构不兼容。

机制：

- storage 读写必须 try/catch。
- JSON parse 失败时清理 key。
- 缓存结构加 version。
- 存储失败时降级内存缓存。

## 11. 高风险写操作兜底

### 11.1 幂等键

适用：

- 创建订单
- 支付
- 提交审批
- 生成账单
- 批量任务

机制：

- 前端生成 `requestId` 或 `idempotencyKey`。
- 后端同一个 key 只处理一次。
- 超时后通过 key 查询结果。

### 11.2 提交结果未知

写操作超时，不代表后端没成功。

机制：

- 不立即允许用户重复提交。
- 显示“正在确认结果”。
- 根据 requestId 查询状态。
- 确认失败后再允许重试。

### 11.3 乐观更新回滚

适用：

- 点赞
- 收藏
- 开关状态
- 非关键轻量操作

不适用：

- 支付
- 删除
- 审批
- 金额变更

### 11.4 撤销操作

适用：

- 草稿删除
- 标签删除
- 归档
- 非核心文件删除

机制：

- 短时间内允许撤销。
- 后端软删除或延迟删除。
- 超时后真正不可恢复。

## 12. 鉴权和权限兜底

### 12.1 Token 刷新队列

多个接口同时 401 时：

- 第一个请求触发 refresh token。
- 其他请求进入等待队列。
- 刷新成功后重放队列。
- 刷新失败后统一退出登录。

### 12.2 权限信息失败

原则：权限不确定时，默认收紧。

机制：

- 不展示敏感菜单。
- 默认进入安全首页。
- 提示“权限加载失败”。
- 不用本地旧权限做最终判断。

### 12.3 多标签登录状态同步

机制：

- `BroadcastChannel`
- storage event
- 退出登录广播所有标签页。
- Token 刷新同步到其他标签页。

## 13. 实时通信兜底

### 13.1 WebSocket

机制：

- 心跳检测。
- 自动重连。
- 重连退避。
- 断线提示。
- 重连后拉取增量数据。
- WebSocket 不可用时降级轮询。

### 13.2 轮询

适用：

- 长任务状态
- 导出任务
- 支付结果确认
- AI 生成任务

机制：

- 设置最大轮询次数。
- 页面隐藏时降低频率。
- 任务完成后停止。
- 失败后允许手动刷新。

## 14. 上传下载兜底

### 14.1 文件上传

机制：

- 上传前校验大小和类型。
- 上传中显示进度。
- 失败后允许重试。
- 大文件分片上传。
- 网络中断后断点续传。
- 表单提交前确认文件上传完成。

### 14.2 文件下载

机制：

- 小文件同步下载。
- 大文件异步任务。
- 文件生成中显示进度。
- 失败后显示原因。
- 导出完成后通知用户。
- 失败项可下载错误报告。

## 15. 静态资源和发布兜底

### 15.1 新版本 chunk 失败

机制：

- 构建产物带版本号。
- 检测版本变化。
- chunk 加载失败时提示刷新。
- 保留上一版静态资源。

### 15.2 CDN 和资源

机制：

- 图片失败显示默认图。
- 头像失败显示默认头像或首字母。
- 字体失败回退系统字体。
- CDN 失败切换备用域名。
- 第三方脚本失败隐藏相关模块。

### 15.3 部署回滚

机制：

- 保留上一版本产物。
- 支持快速回滚。
- 功能开关可关闭新功能。
- 监控发现 P0/P1 自动告警。

## 16. 第三方能力兜底

### 16.1 第三方 SDK

适用：

- 地图
- 支付
- IM
- 验证码
- 埋点
- 客服
- 播放器

机制：

- SDK 加载超时提示。
- 不可用时隐藏对应功能。
- 提供备用入口。
- 第三方错误单独上报。

### 16.2 地图

机制：

- 地图失败显示文本地址。
- 提供复制地址。
- 定位失败允许手动选择。
- 地图不可用不影响表单提交。

### 16.3 图表

机制：

- 数据为空显示空状态。
- 渲染失败显示表格数据。
- 大数据降采样。
- 图表错误不影响页面其他区域。

### 16.4 富文本

机制：

- 编辑器失败降级 textarea。
- 展示端做 HTML 安全清洗。
- 解析失败显示纯文本。
- 自动保存草稿。

## 17. 运行时环境兜底

### 17.1 SSR / SSG

机制：

- 服务端接口失败返回可降级页面。
- 非核心区块失败不阻断主内容。
- 静态生成失败保留上一版页面。
- 增量生成失败继续使用旧页面。

### 17.2 Hydration

机制：

- 服务端不直接依赖 `window`、`document`。
- 客户端专属组件延迟渲染。
- 时间、随机数、本地配置保持一致。
- 水合失败时局部客户端重渲染。

### 17.3 Service Worker

机制：

- 注册失败不影响主应用。
- 缓存损坏时清理并重载。
- 新版本安装后提示刷新。
- 网络失败时回退缓存页面。

### 17.4 低端设备和弱网

机制：

- 检测设备内存、网络类型、帧率。
- 关闭复杂动画。
- 图片降级。
- 图表减少数据点。
- 非关键接口延后请求。

### 17.5 时间偏差

适用：

- 倒计时
- 支付过期
- 优惠券过期
- 考试系统

机制：

- 关键时间以服务端为准。
- 计算客户端和服务端时间差。
- 显示时明确时区。

## 18. 浏览器能力兜底

### 18.1 复制、分享、打印

复制：

- 优先 Clipboard API。
- 失败时显示文本让用户手动复制。

分享：

- 优先 Web Share API。
- 不支持时显示二维码或复制链接。

打印：

- 打印样式单独维护。
- 打印失败提供 PDF 下载。

### 18.2 权限能力

适用：

- 摄像头
- 麦克风
- 定位
- 剪贴板

机制：

- 权限被拒绝时说明原因。
- 提供手动输入替代路径。
- 不把权限拒绝当作系统错误。

### 18.3 可访问性

机制：

- 图片有 alt。
- 表单错误能被读屏识别。
- 弹窗能键盘关闭。
- 元素可聚焦。
- 颜色不作为唯一状态表达。
- 尊重 `prefers-reduced-motion`。

## 19. 业务连续性兜底

### 19.1 支付

机制：

- SDK 回调不是最终结果。
- 以后端订单状态为准。
- 结果未知时轮询确认。
- 不允许重复支付。

### 19.2 审批

机制：

- 提交前展示摘要。
- 失败保留审批意见。
- 状态变化后提示刷新。
- 无权限时隐藏操作。

### 19.3 批量操作

机制：

- 执行前展示影响范围。
- 大批量改为异步任务。
- 显示成功、失败、跳过数量。
- 失败项可下载。
- 支持只重试失败项。

### 19.4 导入导出

导入：

- 校验文件大小和类型。
- 返回错误行。
- 支持下载错误报告。

导出：

- 小数据同步导出。
- 大数据异步导出。
- 超大范围提示缩小筛选条件。

## 20. 监控和告警

### 20.1 生产环境必须能定位

建议接入：

- Sentry
- 阿里云前端监控
- 腾讯云前端性能监控
- Datadog
- New Relic
- 自建日志平台

### 20.2 错误上报字段

至少包含：

- 错误类型
- 错误消息
- 调用栈
- 页面 URL
- 路由名称
- 用户 ID 或匿名 ID
- 浏览器信息
- 设备信息
- 应用版本
- 构建版本
- 接口状态码
- 接口 traceId

不要上报密码、Token、身份证、手机号等敏感信息。

### 20.3 错误分级

```text
P0：全站白屏、登录不可用、核心流程不可用
P1：核心页面不可用、支付/提交失败
P2：局部模块失败、有替代路径
P3：非核心体验问题、偶发错误
```

### 20.4 日志采样

机制：

- 同类错误合并。
- 高频错误采样。
- P0/P1 全量上报。
- 避免日志系统被打爆。

## 21. 功能开关和安全模式

### 21.1 功能开关

适用：

- 新功能灰度
- A/B 测试
- 紧急下线
- 高风险功能

机制：

- 远程开关控制功能。
- 异常时可远程关闭。
- 关闭后回到旧流程或隐藏入口。

### 21.2 安全模式

适用：

- 本地缓存损坏
- 配置异常
- 用户偏好导致崩溃
- 页面刷新仍崩溃

机制：

- 提供安全模式入口。
- 禁用自定义配置。
- 使用默认主题、默认语言、默认布局。
- 清理非必要缓存。

### 21.3 防崩溃循环

机制：

- 记录短时间内崩溃或刷新次数。
- 超过阈值后进入安全模式。
- 清理本地缓存。
- 禁用可疑功能开关。

## 22. 低代码、微前端和复杂架构

### 22.1 微前端

机制：

- 子应用加载失败不影响主应用。
- 子应用崩溃显示局部错误页。
- 子应用超时提供重试。
- 主应用提供统一错误边界。
- 子应用资源版本不兼容时提示刷新。

### 22.2 低代码渲染

机制：

- schema 校验。
- 未知组件显示占位。
- 组件配置错误不影响整页。
- 配置版本不兼容时提示升级。
- 渲染错误定位到组件路径。

### 22.3 动态配置

机制：

- 配置加载失败使用内置默认配置。
- 配置解析失败上报。
- 关键配置做 schema 校验。
- 配置版本不兼容时阻断高风险操作。

## 23. 常见反模式

不要这样做：

- 所有错误只弹一个 Toast。
- catch 以后什么都不做。
- 一个非核心接口失败导致整页不可用。
- 所有请求都全屏 loading。
- 页面只写成功状态。
- 写操作超时后直接让用户重复提交。
- 权限接口失败后继续使用旧权限。
- 第三方 SDK 失败拖垮主页面。
- 生产环境暴露错误堆栈。
- 监控只记录错误，不记录上下文。

## 24. 机制选型原则

### 24.1 按业务风险

高风险业务必须加强兜底：

- 支付
- 订单
- 审批
- 医疗
- 金融
- 法律
- 数据删除
- 权限管理
- 文件上传

低风险业务可轻量处理：

- 推荐内容
- 非核心统计
- 装饰图表
- 首页运营位

### 24.2 按用户损失

如果失败会导致：

- 钱损失
- 数据丢失
- 审批错误
- 重复提交
- 权限越界
- 用户无法继续工作

必须设计强兜底。

### 24.3 按恢复成本

恢复成本越高，越要提前兜底：

- 长表单要草稿。
- 支付要结果确认。
- 删除要撤销或软删除。
- 大文件上传要断点续传。
- 多人编辑要冲突处理。

## 25. 落地路线图

### 25.1 所有项目必须做

- 统一请求封装。
- loading、empty、error 状态。
- 表单校验。
- 提交防重复。
- 路由 404。
- 登录过期处理。
- 全局错误处理。
- 危险操作二次确认。

### 25.2 中后台项目建议做

- 路由权限兜底。
- 按钮权限兜底。
- 动态路由刷新恢复。
- 字典缓存兜底。
- 详情页错误重试。
- 批量操作失败明细。
- 导入导出兜底。

### 25.3 复杂业务项目强烈建议做

- 幂等键。
- 提交结果未知确认。
- Token 刷新队列。
- 本地草稿。
- 乐观更新回滚。
- 并发编辑冲突处理。
- WebSocket 重连和轮询降级。
- 监控告警。
- 功能开关。

### 25.4 高可用项目必须评估

- 离线模式。
- Service Worker。
- 多标签页同步。
- CDN 备用域名。
- 微前端隔离。
- SSR/SSG 兜底。
- 部署快速回滚。
- 安全模式。
- 稳定性演练。

|------|----------|--------|

| 接口失败 | 请求错误、局部错误状态、重试 | P0 |
| 登录过期 | 401 处理、清理登录态、跳登录 | P0 |
| 无权限 | 403 页面、按钮权限、后端兜底 | P0 |

| 资源失败 | 懒加载 fallback、新版本刷新提示 | P1 |

## 27. 持续吸收规则

### 27.1 什么机制应该加入本文

符合以下任一条件，都可以加入：

- 避免页面白屏。
- 避免局部错误扩散。
- 接口失败后可恢复。
- 网络异常下可降级。
- 数据提交失败后可补偿。
- 用户误操作后可撤销。
- 新版本发布后可回滚。
- 第三方服务不可用时有替代路径。
- 缓存、离线、弱网环境下仍可用。
- 能降低用户损失、业务损失或排查成本。

## 28. 事故复盘模板

线上故障后，应补充到本文或事故库：

```text
事故标题：
发生时间：
影响范围：
用户表现：
根因：
为什么没有提前兜底：
临时处理：
长期修复：
新增兜底机制：
需要加入本文的位置：
```

复盘必须问：

- 错误为什么能扩散？
- 是否缺少局部错误边界？
- 是否缺少错误状态？
- 是否缺少重试或恢复入口？
- 是否缺少监控告警？
- 是否缺少灰度或开关？
- 是否缺少回滚能力？
- 用户是否知道下一步做什么？
- 开发者是否能快速定位？

## 29. 稳定性测试清单

开发完成后至少验证：

- 页面首次加载成功。
- 页面刷新后仍能访问。
- 断网时有提示。
- 接口 401 能重新登录。
- 接口 403 显示无权限。
- 接口 404 显示不存在。
- 接口 500 显示失败并可重试。
- 空数据不是空白页面。
- 重复点击不会重复创建。
- 懒加载失败不是白屏。
- 局部模块失败时其他模块仍可用。
- 返回上一页和返回首页可用。
- 生产环境不显示错误堆栈。
- 错误能在监控系统查到。

复杂项目建议额外演练：

- CDN 异常。
- SDK 加载失败。
- localStorage 损坏。
- Token 刷新失败。
- 多标签页退出登录。
- 新版本 chunk 加载失败。
- 大文件上传中断。

## 30. 最终标准

一个前端项目的兜底机制合格，不是指没有错误，而是：

```text
错误被限制在最小范围。
用户知道发生了什么。
用户知道下一步能做什么。
开发者能定位错误来源。
其他页面和模块不被拖垮。
```

这是任何前端项目都应该具备的稳定性底线。
