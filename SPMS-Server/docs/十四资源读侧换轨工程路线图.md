> `ownerColumns` 归属语义的业务资源（物料/库存/订单等），不该套到 personnel 三表上。

## 二、换轨模板（从 `wms.input` 提炼，6 步）

> **J4（2026-09-18）更新**：模板里原来还有"影子读服务"与"第三个 COUNT"两步
> （`XxxReadShadowService` + `RowParityCounter` / `countByPermissionFragment` / `parityResourceKey`）。
> 那两步回答的是"JPA 侧与 Mapper 侧数出来一不一样"，随 `spring-boot-starter-data-jpa` 一起删除，
> **新增资源不要再建这些文件**（建了会被 `pnpm jpa:check` 与 `maskContract` 的退场判据拦下）。
> 现在每个资源的取证由两条既有注入路径统一交给 `ShadowDiffService`，资源侧无需额外接线。

1. **Entity**：确认主实体继承 `TenantAwareEntity`（档 B 先改继承链）；关系对象在 resultMap 中只投影 ID。
2. **`XxxMapper.java`**：`@DataResource(key=..., alias=...)` + `implements KuboBaseMapper<XxxEntity>`，含 5 个方法：
   `selectPageByPermission` / `selectDetailByPermission` / `countByPermission` / `statByPermission` / `selectForExport`。
3. **`XxxMapper.xml`**（`resources/mapper/<模块>/XxxMapper.xml`）：`resultMap`（逐列映射 + 关系 `association` 只投影 id）、`<sql>` 列段 / 业务筛选段、`ORDER BY id DESC`、`LIMIT/OFFSET`。权限条件由 MyBatis-Plus 运行时拦截器（`DataPermissionInterceptor`）在语句编译期改写 AST 注入，**不在 XML 里手写**（占位符注入是 J2 换轨前的形状，已删除）。
4. **`XxxService.java`**：`isMapperReadEnabled()` + `getMapperPage/getMapperDetail/getMapperCount/getMapperStat`，`mapper-read.enabled=false` 时回退到引擎（wrapper）读路径。
5. **`XxxController.java`**：读出口（page/detail/count/stat/export）改走 Mapper 路径。
6. **测试**：`XxxMapperRuntimeInterceptorTest`（当前租户可见行 + 固定 id 倒序 + 无策略恒假零行 + 导出走同一权限链）；回退测试（`mapper-read.enabled=false` 走引擎读路径）；**登记**：`DevDataInitRunner` 补 owner_columns（有归属列的资源）。

## 四、每批验收标准（不可放松）

1. 真实 H2 Mapper 链测试通过（statement/策略/fail-closed）；
2. JPA/Mapper parity（影子双跑）测试通过，两遍行数一致；
3. `mapper-read.enabled=false` 时 Service/Controller 回退 JPA 的功能级测试通过；
4. 导出取数走同一权限链（当前租户可见行 + 无策略恒假零行）；
5. `pnpm ddl:check` / `text:check` / `perms:check` 全绿；CI 三 job 全绿。
