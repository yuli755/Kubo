### 1.2 后端 P0：三个必须优先修的事实

**P0-1 租户 ID 直接信任请求头**（违反审计文档 §2.1「不能只信任请求头」）

```java
// RequestInterceptor.java:160-172
private Long resolveTenantId(HttpServletRequest request) {
    String tenantHeader = request.getHeader("X-Tenant-Id");   // ← 客户端可任意伪造
    ...
    return 0L;                                                  // ← 缺省落到租户 0
}
```

当前不致命（因为还没有租户列），但一旦补上 `tenant_id` 列，这就是**横向越权直通车**。修法：`tenantId` 只能来自服务端（用户 → 租户映射表 / JWT claim），请求头只作为**候选并需校验归属**，校验失败一律拒绝而非回落 `0L`。

**P0-2 业务表根本没有归属列 → 行级过滤静默空转（真正的阻塞项）**

`DataPermissionSpecification` 全部用标量取列：

```java
// :225 / :245
builder.equal(root.get("factoryId"), policy.getSubjectId());
builder.equal(root.get("warehouseId"), policy.getSubjectId());
// :146 catch (IllegalArgumentException) → return null  ← 列不存在 = 静默放行
```

实测归属列盘点（`@ManyToOne` 关系数 / 标量 `xxxId` 列）：

| 实体 | 关联数 | 标量 ID 列 | 结论 |
|---|---|---|---|
| `InventoryEntity` | 3（material/storage/structure） | 无 | 可用 join path 实现 |
| `InputEntity` / `OutputEntity` | 4 / 3 | 无 | 同上 |
| `MoveEntity` | 1 | 无 | 归属路径不足 |
| `OrderEntity` | 3 | 无 | 需确认归属语义 |
| `MaterialEntity` | 1 | 无 | 无租户/负责人 |
| `PurchaseEntity` | **0** | **无** | **完全无归属路径 → 无法接入行级权限** |
| `UserEntity` | 3 | `departmentId` | 可接入 |
| `StorageEntity` / `StructureEntity` | 0 | `parentId` | 树形，需闭包/递归 |

**结论**：整个 schema 里 `tenant_id` 出现 0 次、`factory_id` 0 次、`owner_id` 0 次、`warehouse_id` 0 次。所以阶段 0/1 的"归属建模 + 字段补齐 + 历史回填"**不是已完成，而是尚未开始**；权限内核是"有锁没门"。这决定了后段的**真正顺序**（见第 3 节）。

**P0-3 fail-open 三处 + 无开关**

| 位置 | 行为 | 风险 |
|---|---|---|
| `DataPermissionSpecification:67` | 资源未注册 → 跳过权限 | 忘记注册 = 全量开放，且无人报警 |
| `DataPermissionGuard:40` | 无 context（定时任务/MQ）→ 不拦截 | 旁路点无审计 |
| `DataPermissionSpecification:146,175` | 列不存在 → 跳过该条件 | 即 P0-2 的"看起来生效实际没生效" |
| 全局 | 无 `datapermission.mode = off / shadow / enforce` 配置项，无任何 Micrometer 指标 | 审计文档阶段 7「观察模式」和回滚开关无从执行 |

修法：引入**资源注册守卫 + 三态开关 + 结构化拒绝日志/指标**，把 fail-open 变成"显式声明的例外"（例外必须是配置项 + 记审计，而不是 catch 后 return null）。

## 2. 五个必须先拍板的决策（可行性建议的核心）

| # | 决策点 | 选项 | **推荐** | 代价 / 前置 |
|---|---|---|---|---|
| **D1** | 行级权限"归属"落在哪里 | (a) 给业务表加冗余标量列 `tenant_id/owner_id/factory_id/warehouse_id`；(b) 不改表，谓词改为**关联路径** `root.join("storage").get("id")`；(c) 混合 | **(c) 混合**：租户/负责人走新增标量列（要写路径也要用，必须冗余），仓库/工厂/部门走 join path（已有 `@ManyToOne`，零迁移成本） | `data_resource.owner_columns` 需扩展语法支持 `storage.id` 点号路径；`RowPermissionPredicate` 增加 `association()` 工厂方法 |

| **D4** | 列级脱敏在哪一层做 | (a) 现状：切面反射改**实体字段**；(b) 改 JSON 序列化层（Jackson 序列化器 + `@SensitiveField`）；(c) DTO 化 | **(b)**：`JsonSerializer<Object>` 上挂策略，永不写回实体 | 现状 `ColumnMaskingAspect:110 field.set(obj, …)` 在**同一事务内的托管实体**上写值，`DynamicUpdate` + flush 有把 `138****0000` 落库的风险；审计文档"持久化实体不会被脱敏逻辑污染"这条目前**不满足** |

## 3. 推进路线（前后端两条泳道 + 联合里程碑）

### 3.0 关键顺序原则（与现有规划的差异）

现有施工图把"配策略/写拦截"排在前面，本文把**"归属建模"整体前置**：

```
❌ 旧顺序：内核 → 策略配置 → 拦截器 → 补列（补列被放到阶段 1 末尾，实际被跳过）
✅ 新顺序：归属建模（列/路径 + 回填）→ 内核语义修正（fail-closed + 开关）→ 试点强制 → 推广
```

理由：P0-2 决定了**在此之前任何权限测试都是自证的假绿**（测试用自建 `schema-test.sql`，生产用真实 schema，两边不是一回事）。

### 3.1 后端泳道

| 阶段 | 目标 | 工作项（可勾选） | 通过条件（Gate） | 回滚 | 估时(人日) |
|---|---|---|---|---|---|
| **B0 收口安全债**（先做，1 周） | 让现有代码"不假绿" | ① `tenantId` 改服务端来源 + 拒绝回落 `0L`；② `ddl-auto` production 强制 `validate`；③ 三处 fail-open 加显式告警日志；④ 新增 `DataPermissionProperties`(`mode=off\|shadow\|enforce`) 并把 `Specification`/`Guard` 全量接上；⑤ `@SensitiveField` 脱敏从改实体改为 Jackson 序列化层 | 单测覆盖：伪造 `X-Tenant-Id` 返回 403；`mode=shadow` 不改变结果但产出计数；脱敏后 `repository.saveAndFlush` 断言库内原值不变 | 开关回 `off`（行为等价于今天） | 5–7 |
| **B1 归属建模**（阻塞项，2 周） | 权限有东西可绑 | ① 用附录 A 的扫描脚本产出 24 资源 × 归属列矩阵；② `wms.inventory/input/output/move`、`mes.order/plan/picking` 加 `tenant_id/owner_id`（`@Column(nullable=false)` + 索引）；③ 历史数据回填脚本（默认归属 `tenant=1` + 负责人 = 创建人，需产品确认）；④ `owner_columns` 支持 `storage.id` 点号路径；⑤ `PurchaseEntity` 等**无归属路径**表明确登记为"暂缓接入"并在注册表中写 `status=DRAFT` | `ddl-auto=validate` 下启动成功；`SELECT COUNT(*) WHERE tenant_id IS NULL = 0`；真实 MySQL 上"租户 A 查不到租户 B" 通过 | 列可空 + 开关 off（向前兼容，不删列） | 10–12 |
| **B2 行级语义完整**（2 周） | 六档范围可用 | ① 部门/仓库/工厂树：`parentId` 递归 → 用**内存闭包展开 + Redis 缓存**（首期不上递归 CTE）；② 策略条件补 `ANY_OF/ALL_OF` 组合（现仅单列 equal）；③ 覆盖 **COUNT / 详情 / 更新 / 删除 / 批量 / 导出**（`Curd.Export`、`Curd.QueryExport` 目前 `@Extends` 排除了导出，需单独立项）；④ `PermissionContext.factoryIds` 目前恒为 `Set.of()`，要么建 user→factory 关系，要么从模型中删除该维度（**别留假字段**） | 越权矩阵（第 7 节）后端全绿；分页 `total` 与列表条数一致；导出行数 == 列表可见行数 | 按资源逐个退回 shadow | 8–10 |
| **B3 列级脱敏扩面**（1.5 周） | 覆盖审计文档 9 类敏感字段 | ① `@SensitiveField` 从 3 实体扩到：手机号/身份证/邮箱/地址/采购价/销售价/成本价/薪资/设备密钥；② 脱敏策略补 `FULL/PARTIAL/LAST4/HASH`；③ 嵌套 DTO 与分页 `Map{list}` 之外的结构（当前只认 `list` 键）；④ **导出与明文凭据访问写审计**；⑤ 前端 `my-mask` 已就位 → 视图接 `v-mask`（0 处 → 全量敏感字段） | 无权限角色在接口与导出中都看不到原值；脱敏异常 fail-safe（不泄露原值） | 字段策略按资源停用即可 | 6 |
| **B4 一致性闭环**（2 周） | 变更可靠传播 | ① `permission_change_outbox` **写事务内落库**；② `OutboxDispatcher` 定时轮询 + 指数退避 + 死信 + 人工重放接口；③ 广播消息带 `version`，消费端**版本落后才刷新**（幂等）；④ 指标：待投递数/重试数/传播延迟 | Redis 断线后可补偿收敛；重复消费无副作用；MQ 不接（沿用 Redis Pub/Sub，遵守"首期不引 RabbitMQ"） | 停 Dispatcher，退化为 TTL 过期 | 8 |
| **B5 推广与灰度**（持续） | 逐模块 enforce | 按 `personnel → system → wms → mes → factory → asset/channel/iot` 顺序切 enforce；每模块：观察 3 天 → 强制 → 一周无异常进下一个 | 每模块一份"拒绝原因分布"报告；无 P0 越权 | 单模块回 shadow，互不影响 | 10–15 |

> **不做的**（明确排除，避免被旧文档拉回）：MyBatis-Plus 迁移、gRPC 权限中心、RabbitMQ、Seata、微服务拆分、独立权限缓存中间件。

## 5. 门禁工程化（新增清单，最小可执行）

**前端 `package.json` 需新增：**

```jsonc
"typecheck": "vue-tsc --noEmit",
"test": "vitest run",
"test:e2e": "playwright test",
"check": "pnpm lint && pnpm typecheck && pnpm test",
"size": "node infra/scripts/check-bundle-size.mjs --budget-gzip=800"
```

**`.github/workflows/ci.yml` 两个 job：**

| job | 步骤 | 卡点 |
|---|---|---|
| `web` | `pnpm install --frozen-lockfile` → `lint` → `typecheck` → `vitest` → `build` → **gzip 总量 vs budget** → `api:generate:diff`（生成物与提交不一致则失败，防手写漂移） | 体积超预算 / 类型错误 / 无测试通过 → 直接 fail |
| `server` | `mvn -B verify`（含 `DataPermission*Test`）→ **`integration-test` 起 mysql+redis service 容器** → 越权矩阵用例 → `jdeps/依赖黑名单`（禁止出现 `mybatis`、`spring-boot-starter-amqp`、`tailwindcss`） | 越权用例任一失败 → fail；引入被否决依赖 → fail |

**必须新增的 3 个脚本（都是"防倒退"，不是"造功能"）：**

1. `infra/scripts/check-permission-codes.mjs`：比对 `src/config/permissions.ts` 与后端 `scanPermission()` 产出的权限标识集合，缺/多即失败（防 D5/F1 漂移）。
2. `infra/scripts/check-bundle-size.mjs`：`dist` gzip 汇总 + 单 chunk 上限，写回 PR comment 形成趋势。
3. `SPMS-Server/tools/scripts/scan_attribution.py`（或 shell）：扫全部 `@Entity`，输出 `resource_key → 标量归属列 / 关联路径 / 是否可接入`，即附录 A 的自动生成器 —— **B1 的唯一可信输入，别让盘点停留在手工表格**。

**数据权限灰度配置（B0 引入）**：

```yaml
kubo:
  data-permission:
    mode: shadow          # off | shadow | enforce
    enforce-resources:    # enforce 白名单，逐资源开闸
      - wms.inventory
    audit-log: true
    fail-closed-on-unregistered: false   # B5 结束后改 true
```
