## 2. 关系投影与补齐

主表 SQL 一律禁止使用未在权限注册表登记的跨资源隐式 JOIN，防止非预期绕过 fail-closed。关联对象在主表 SQL / ResultMap 中先投影关联主键 ID，详情及补齐阶段再沿各自资源 Service 独立读取：

| 资源 | 主表投影的关系 ID | 补齐路径（详情出口） |
| --- | --- | --- |
| `asset.material` | `unit_id` | `unitService.get`（非租户公共字典单位） |
| `asset.contract` | `documentList` / `participantList` | 多对多关系，`getMapperDetail` 先经 Mapper 校验存在性与权限，再走 JPA `get(id)` 沿关系拉取 |
| `channel.customer` | 无（独立表） | 直接返回实体 |
| `channel.supplier` | 无（独立表） | 直接返回实体 |
| `channel.purchase` | `details` 明细 | `purchaseDetailService` 关联查询 |
| `channel.sale` | `customer_id`、`details` 明细 | `customerService.get`、`saleDetailService` 关联查询 |
| `channel.purchasePrice` | `material_id`、`supplier_id` | `materialService.get`、`supplierService.get` |
| `channel.salePrice` | `material_id`、`customer_id` | `materialService.get`、`customerService.get` |
| `factory.storage` | `parentId` | 树形结构；Mapper 承载扁平读出口，树导航由 JPA `getList` 承担 |
| `factory.structure` | `parentId`、`operationList` | 树形结构；Mapper 承载扁平读出口，LAZY 关系在详情层经 JPA 补齐 |
| `wms.inventory` | `material_id`、`storage_id`、`structure_id` | `materialService`（Mapper 开→`getMapperDetail`，关→`get`）、`storageService.get`、`structureService.get` |

**导出路径不补齐关系实体**：导出列严格遵循 `@Export` 标注的标量字段（见 §3），非标量关系字段不标 `@Export`，`EntityCsvExport` 会自动跳过它们。列表导出不会把未脱敏的关系实体 `toString` 写进 CSV，更不会逐行触发跨资源级联读取。

## 4. 导出编排与脱敏流控

导出的完整执行链路如下：
```
Controller.export(QueryListRequest)
  │
  ├─► [isMapperReadEnabled() == false] ──► super.export() (JPA 回退链路)
  │
  └─► [isMapperReadEnabled() == true] (MyBatis-Plus 读侧换轨链路)
        │
        ├─ 1. Mapper.selectForExport(filter) (受 MyBatis 运行时拦截器权限注入与当前租户隔离)
        ├─ 2. ExportColumnMasker.maskForExport(rows) (请求线程上下文识别敏感列并脱敏，如价格遮蔽)
        ├─ 3. CsvFormulaSanitizer.sanitize(masked) (防 CSV 公式注入过滤)
        ├─ 4. EntityCsvExport.toCsvInputStream(sanitized, Entity.class) (流式写入，带表头与字典转换)
        └─ 5. ExportHelper.saveExportFileStream(stream) (安全落盘并生成下载文件编码)
```

## 6. 统计出口（count/stat）统一口径

十四个资源统一采用 `ReadStat{total, publishedTotal}` 模型：
- `count` 与 `stat.total`：复用主查询同套 `XFilter` 权限语句计算权限范围内总记录数；
- `stat.publishedTotal`：计算同一权限范围内 `is_published = TRUE` 的有效行数；
- 统计接口仅做行数统计，不包含价格/金额等敏感聚合，天然杜绝通过统计旁路反推明细数据的安全隐患；
- 单据类与流转类资源（入库、出库、移库、采购、销售）生命周期主要由状态（`status`）驱动，`is_published` 通常为 `false`（`publishedTotal = 0`），统一保留该字段是为了维持全栈契约的一致性。

## 8. 前端导出对接与权限体系
