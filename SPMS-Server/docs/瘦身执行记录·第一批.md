- `vite.config.mts`：删除 `/websocket` 代理
- `nginxContract.spec.ts`：删 3 条 WS 用例，文件头注释改为"REST + 静态资源"两条，并写明**如将来加实时通道（SSE/MQ）需在此重新加契约**
- `stores/user.ts` + `stores/__tests__/user.spec.ts`：删除登出时的断 WS 副作用与对应断言
- `Console.vue`：删除 WS 连接与 `isDemoRuntime()` 跳过逻辑（没有通道可连了）
- 注释清理：`runtimeFlags.ts`、`demo/index.ts`、`errorHandler.ts`（保留 `websocket` 作为**错误上下文示例词**，非代码依赖）

## 5. 演示模式（预览）· 三道闸 —— 本次交付的运行机制

需求是"临时关掉登录看全部页面，但真库接上时必须能干净地摘掉"。落地为**三道闸**，任一道都足以阻止"绕过登录的后门"进生产：

| 闸 | 位置 | 作用 |
| --- | --- | --- |
| ① 构建期插件 | `infra/plugins/demo-gate.ts` | `--mode demo` **只允许 serve，不允许 build**：`vite build --mode demo` 直接抛错 |
| ② 编译期常量 | `src/config/buildFlags.ts` + `main.ts` | `DEMO_ENABLED = import.meta.env.MODE === 'demo'`，生产构建折叠为 `false` ⇒ `await import('@/demo')` 是死代码，**演示模块不产出 chunk** |
| ③ CI 产物扫描 | `infra/scripts/check-demo-build.mjs`（`pnpm demo:check`，已接入 `ci.yml` + `pnpm check`） | 扫 `dist/**/*.js`，命中 `KUBO_DEMO_MODE_v1` / `__KUBO_DEMO__` / `installDemoMode` 即失败 |

### 5.1 踩到的两个真坑（已修，值得记住）

1. **`define` 只在 build 生效，dev 不替换** —— 初版用 `define: { __DEMO_ENABLED__: ... }`，
   dev 下标识符原样保留 ⇒ 运行到 `if (__DEMO_ENABLED__)` 直接 `ReferenceError` ⇒ **预览必崩**。
   改为 `import.meta.env.MODE`：dev/build 都可用，build 下同样能被常量折叠。
2. **运行时标记本身是个后门** —— 初版 `isDemoRuntime()` 只读 `window.__KUBO_DEMO__`，
   意味着**线上任何人在控制台手写这一行就能把自己变成演示环境**。
   改为 `DEMO_ENABLED && window.__KUBO_DEMO__` 双条件：生产构建下整个函数折叠为 `false`，
   字符串 `__KUBO_DEMO__` 一并被消除。

### 5.2 怎么用

```bash
pnpm dev:demo     # 演示预览：mock 接管全部接口 + 预置登录态（跳过登录）
pnpm dev          # 正常开发（需要后端）
VITE_LEGACY_SHELL=true pnpm dev   # 旧壳 A/B 对比（评审用，评审完删分支）
pnpm demo:check   # 本地复跑③；CI 已在 build 后自动执行
```

**接真库时怎么摘**：删 `src/demo/**`、`src/config/buildFlags.ts` 里的 `DEMO_ENABLED` 分支、
`infra/plugins/demo-gate.ts`、`infra/scripts/check-demo-build.mjs` 与两处接线（`ci.yml`/`package.json`）
即可，业务代码零改动（业务侧只依赖"请求走 axios"，适配器被替换在 `axios.defaults.adapter` 层）。

## 6. 视觉方向 B（深色侧栏 + 浅色工作区）· 本次落地

**根因**：新壳 `KAppShell.vue` 引用了 9 个**在 `tokens.scss` 里根本不存在**的 token
（`--kubo-color-bg-sider`、`--kubo-sider-width`、`--kubo-header-height` …），CSS 变量取不到值 ⇒
侧栏透明、菜单走 EP 浅色默认样式 ⇒ 就是那句"**焕然一新的感觉没效果**"。

**修复**：
1. `tokens.scss` 补布局骨架 token 与侧栏专用色（`#001529` 深蓝底 / 白字 72% / 悬停白 8% / 激活实心主色），
   面层色（`--kubo-color-bg-page` 等）**引用 `--el-bg-color-*`**，暗色模式自动跟随 EP，少一处会忘的同步点；
2. `KAppShell.vue` 补 `.k-menu` 配套样式——用 EP 的 `--el-menu-*` 变量接管配色（不再层层 `:deep()` 穿透），
   当前页用**实心主色块**定位，父级展开只提亮文字；
3. 品牌区/收起按钮原先误用浅色面层 token（深色侧栏上会不对），改用侧栏专用 token；
4. `element-plus-aggregate.ts` 按该文件约定补 `ElDrawer` / `ElBreadcrumb(+Item)` / `ElScrollbar` 三个子路径 re-export
   （漏一个就 `pnpm build` 报 "not exported"）。

**验证**：`pnpm build` ✅ · `pnpm size` 首屏 281.8/450 KB、总体 847.7/900 KB ✅ · 演示服务 `curl` 8 个关键模块全 200。
