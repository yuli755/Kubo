## 二、前端架构（自研底座，已无 airpower）

### 2.1 底座怎么分层

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 框架层 | `src/framework/**` | 元数据装饰器（`@KModel/@KTable/@KForm/@KField/@KSearch`）、`RootEntity`、HTTP/服务基类（`AbstractCurdService`）、查询模型（`QueryRequestPage` 等）、反馈（toast/确认/命令式弹窗 `DialogUtil`）、枚举字典、格式化、单元格、导出、上传、脱敏 |
| 组件层 | `src/component/framework/K*.vue` | `KTable` / `KFormDialog` / `KPanel` / `KSelector` / `KDetail` / `KDetailTable` / `KDialog` / `KUpload` |
| 应用外壳 | `src/component/{KAppShell,Console,ErrorBoundary,UserCard}.vue` | 侧栏 + 面包屑 + 抽屉、动态菜单路由注册、错误兜底、账号中心 |
| 数据层 | `src/hook/kubo/{useTable,useDetail}.ts` + `src/hook/<域>/*` | 列表/详情状态与请求流；视图不直连 Service，统一经 hook 转发（ESLint 拦） |
| 视图层 | `src/view/console/<域>/...` | 路由路径 == 视图路径；菜单由后端下发 |

**关键约定**：实体只挂 `@K*` 装饰器（不再有双注册）；模板里的 `<el-*>` 必须显式 import；
新用到的 Element Plus 组件要补进 `src/types/element-plus-aggregate.ts`（`elementPlusAggregate.spec.ts` 会拦漏项）。

### 2.2 视觉与主题

- 方向 **B（数据密集型）**：深色侧栏 + 浅色工作区、紧凑行、语义化状态色。
- 设计 token 层 `src/styles/tokens.scss`（映射 `--el-color-*` / `--kubo-*`）+ `motion.scss`；暗色走 EP 官方 `dark/css-vars`。
- Element Plus 中文语言包由 `main.ts` 的 `provideGlobalConfig({ locale: zhCn }, app, true)` 提供（本轮修复：此前挂在无人读取的配置上，日期/分页/确认框一直是英文）。

## 七、怎么复现/自检这套结论

```bash
pnpm stack:project                 # 本文件的机器版（本次实测：前端 9 + 15 个依赖；后端 12 个依赖；16 个 compose 服务）
pnpm stack:project -- --json       # 给脚本读
pnpm stack                         # 前端：依赖 + 死重量 + 体积
pnpm airpower:check                # 前端 airpower = 0
pnpm airpower:backend              # 后端 airpower 足迹 + 要自建清单
pnpm airpower:backend -- --check   # 后端棘轮（CI 已接；基线写在脚本里，只许降）
pnpm pom:check                     # 后端 pom 自持校验（B0 之后没有父 POM 兜底）
pnpm check                         # 前端全链门禁（16 道）
pnpm java:unit                    # 需 JDK 17（JAVA_HOME）：仅编译/运行独立工具契约
cd SPMS-Server && ./mvnw -B -s settings.xml compile && ./mvnw -B -s settings.xml test  # 整仓验收仍必需
```
