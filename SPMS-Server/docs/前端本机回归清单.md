# 前端本机回归清单（方向 5「去 airpower 化入口」）

> 背景：方向 5 把首屏的 airpower 依赖整体迁出（RouterUtil/WebConfig/ValidateUtil 复刻 +
> axios 单独拆 chunk），首屏 365 → 270.2 KB。静态门禁（typecheck/lint/215 单测/build/体积/
> 5 个 infra 校验）在沙箱内已全绿，但**运行时正确性（视觉 + 后端联调）无法在沙箱验证**，
> 需本机跑一遍确认。

## 一、启动

```bash
pnpm install
pnpm dev        # 起前端，默认 http://localhost:3000
# 后端按 SPMS-Server 的本地启动方式拉起（数据库 + 服务）
```

## 二、视觉回归（airpower CSS 剥离的遗留风险）

方向 5 前一轮的 `airpower-css-strip` 插件删掉了 web.css 里与 element-plus 重复的样式，
只保留 airpower 自身样式 + 独用组件。**重点看这些组件的渲染是否正常**：

- [ ] 表格（ATable → el-table）：表头/多选/列头 tooltip/滚动
- [ ] 菜单（AMenu → el-menu / el-sub-menu）：折叠、悬停高亮
- [ ] 图片（AImage → el-image）：缩略图、预览弹层
- [ ] 上传（AUpload → el-upload）：拖拽区、进度条
- [ ] 分页（APage → el-pagination / el-pager）
- [ ] 弹层（ADialog/APopover → el-popover）
- [ ] 级联选择（AInput cascader 模式 → el-cascader）
- [ ] 深色模式（html.dark）：以上组件在暗色下对比度正常

发现视觉异常时：截图 + 页面路径 + 组件名，回贴给我定位（大概率是某个 el 组件样式被
误删，白名单 `infra/plugins/airpower-css-strip.ts` 的 `AIRPOWER_ONLY_EL` 需补）。

## 三、登录 / 鉴权链路（方向 5 迁移的核心）

- [ ] 登录：账号密码 → 跳转控制台（登录页已改用 `useRoute()` + 本地正则校验）
- [ ] 刷新后 token 不丢（token 存 `Authorization` key，兼容层见 `@/utils/airpowerCompat`）
- [ ] 退出登录：清空本地状态、摘 token、断开 WS、清权限（后端登出失败也要清本地）
- [ ] token 过期 → 自动 refreshToken 或跳回登录
- [ ] 第三方登录 / 授权回调（authorize / bind / callback 页已改用 `useRoute()`）

## 四、菜单 / 权限（动态路由复刻）

- [ ] 不同角色登录，左侧菜单按权限正确渲染
- [ ] 首次进入 Console 时 airpower 懒加载正常（此时才加载 vendor-airpower 79.5 KB）
- [ ] 无权限路由跳转 error 页；手动输入无权限 URL 被拦

## 五、一处需你确认的语义变化

`@/utils/validators.ts` 复刻 `ValidateUtil.isNaturalNumber` 时，把 airpower 原正则
`^\d+((.)\d+)?$` 的**未转义点号 `(.)`** 修正为小数点 `\.`。原实现疑似上游笔误（`(.)`
匹配任意字符）。请确认登录页**小数输入**场景行为符合预期。

## 六、体积门禁参考

```bash
pnpm size   # 应输出：首屏 270.2/450 KB · 总体 832.5/900 KB ✅ 达标
```

若你本机 `pnpm build` 后 `pnpm size` 数字与上述有差异，通常是依赖版本 / lockfile 差异，
不影响判定，重点看是否「达标」而非绝对数字。
