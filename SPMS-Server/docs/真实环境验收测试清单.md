## D. 权限变更事件与 Outbox（P5，本轮新写）

### D1 写侧落库（Recorder）
- **测**：改一条策略 → 查 `permission_change_outbox` 出现一行 `PENDING`，`event_key` 唯一、`payload` 为事件 JSON。
- **期望**：变更与 outbox 同事务（变更回滚则 outbox 无残留）。
- **失败意味**：落不下 = 变更没持久化记录。
- [ ] 通过

### D2 Dispatcher 重投（默认关 → 开）
- **前提**：真实 Redis；`kubo.data-permission.outbox.enabled: true`。
- **测**：手动把一行置 `PENDING` 且 `next_retry_at` 过期；观察 `@Scheduled` 轮询是否把它重投到 `spms:datapermission:changes`、状态变 `DONE`。
- **期望**：到期行被拉取、投递成功 → DONE + processed_at；投递失败 → retry_count+1、按退避排下次、5 次后 DEAD + last_error。
- **失败意味**：Dispatcher 不轮询（查 `@EnableScheduling` 与开关）、或缺 Redis、或缺依赖。
- [ ] 通过

### D3 消费幂等（重复投递无副作用）
- **测**：对同一 event_key 重投多次，观察各节点缓存失效结果。
- **期望**：无副作用（清缓存可重放）。
- [ ] 通过

### D4 死信重放 / 丢弃（人工补偿，本轮新写）
- **前提**：D2 完成；`permission_change_outbox` 至少有一行 `DEAD`（可用错误 payload 造出，或手动把一行置 `DEAD`）。
- **测**：
  1. `GET /dataResource/outbox-dead`（用持有 `system:data-permission:outbox` 的账号）→ 返回 DEAD 列表（最新在前，≤100 条）。
  2. 无权限账号调同一接口 → 403，且 `data_permission_deny_log` 出现 `outbox-denied`。
  3. `POST /dataResource/outbox-replay`（body `{"eventKey":"..."}`）→ 该行变 `PENDING`、`retry_count=0`、`next_retry_at`≈当前时刻、`last_error` 清空；下一轮 Dispatcher 把它拉走重投（状态转 `DONE`）。审计日志出现 `outbox-replayed`。
  4. `POST /dataResource/outbox-replay-all` → 所有 DEAD 行全部回到 PENDING，返回重放条数。
  5. `POST /dataResource/outbox-discard`（body `{"eventKey":"..."}`）→ 该行被删除，审计日志出现 `outbox-discarded`。
- **期望**：重放只对 `DEAD` 行生效（对非 DEAD 行返回参数错误）；每次重放/丢弃都落审计（谁、何时、哪条 event_key）。
- **失败意味**：死信不能恢复 = 变更通知可能永久丢失；重放/丢弃不留痕 = 特权操作不可追责。
- [ ] 通过

- **期望**：敏感列脱敏，与界面一致。
- [ ] 通过

### E4 死信管理面板（本轮新写）
- **前提**：D2/D4 完成；用 `system:data-permission:outbox` 账号登录。
- **测**：打开「系统 → 数据权限 → 数据资源」页，滚动到「权限变更死信」区块。
  - 有 DEAD 行时：显示事件键/类型/重试次数/最后错误 + 「重放 / 丢弃」按钮 + 「重放全部」。
  - 点「重放」→ 二次确认 → 该行从列表消失（回到 PENDING 被 Dispatcher 拉走）；审计日志出现 `outbox-replayed`。
  - 点「重放全部」→ 二次确认 → 全部消失。
  - 点「丢弃」→ 二次确认 → 该行消失；审计日志出现 `outbox-discarded`。
  - 无 DEAD 行时不显示区块；无 `outbox` 权限账号调用 → 接口 403（前端提示），区块不显示数据。
  - 后端不可达时：显示「未能取得死信列表」，不显示成「没有死信」。
- **期望**：前端只回显与触发，不重算状态迁移；重放/丢弃失败必须有可见提示（toast）。
- **失败意味**：面板把「取不到」显示成「没有死信」= 死信被静默遗忘；失败无提示 = 特权动作结果不可见。
- [ ] 通过
