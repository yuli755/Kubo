# 业务功能未开发 / 未实现盘点（2026-09-10）

> 触发：用户要求盘点「各业务系统里哪些模块没开发、哪些模块的哪些功能没实现、是否还有类似情况」。
> 方法：对后端 50 个 Controller、前端 144 个 .vue、菜单初始化（`MenuService.initMenu`）、迁移脚本、
> 全仓 TODO/空壳/占位做了系统性扫描。**只列代码事实可证的点，不臆测「业务还该有什么」**。

## 0. 结论先行

- **整模块未开发：1 个** —— 聊天（后端完整、前端零）；微信、企业微信历史空壳已彻底清零。
- **具体功能点未实现：0 个** —— 短信验证码（策略化+自持阿里云POP通道闭环）、仓储流转与报工并发分布式锁（自持分布式互斥+原子UPDATE闭环）；历史工序BOM/前端RSA/WebAuthn占位均已随模块清理彻底移除。
- **文档已记录的未闭环：收敛为 4 类**（导出流脱敏穿透、写侧归属不可变硬校验、仓储并发锁均已闭环，余下为 v-mask 视图铺开等长尾项）。
- **易误判为「未实现」但实际已闭环：3 处**（IoT 时序、OAuth2 第三方登录、MCP），见 §4。

核心判断：**「业务 CRUD 骨架」基本齐全且前后端闭环**（所有菜单项都有对应页面）；历史残留的
「非 CRUD 的增值功能」（即时通讯、外部平台集成、短信通道）与「写侧健壮性」（并发锁、事务边界）均已得到系统化治理与收敛。
