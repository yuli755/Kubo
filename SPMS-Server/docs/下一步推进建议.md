## P2 · 决策点 ✅ 已落地（2026-09-09）

1. **ErrorCode 统一错误码**：深入核实后发现项目实际有**三套错误码并存**——airpower `Errors`（框架层，代码已在用）+ 项目 `CustomError`（业务层，implements `IException`）+ 冗余 `ErrorCode`（560 行、零引用、code 空间与前两者冲突）。「接线 ErrorCode」会制造第二套业务错误码，故改为：**删除冗余 `ErrorCode`**，`CustomError` 确立为业务错误码唯一落点，3 份规范示例（CODE_STYLE_GUIDE / SECURITY_GUIDE / TESTING_STRATEGY）由假想的 `BusinessException(ErrorCode.XXX)` 改为真实范式 `CustomError.XXX.show()` / `throw new ServiceException(Errors.PARAM_INVALID.getCode(), msg)`。
2. **packages/api-client 占位包**：✅ 保留（Phase 2 迁移 `src/api` 时启用）。
3. **仓库树层级展开**（`hierarchy.factory-enabled`，§19.28）：等真实环境影子账数据再拍，现默认 false 是安全态。
