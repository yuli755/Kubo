## 2. 关系投影与补齐

主表 SQL 一律不 JOIN 跨资源表（禁止用未登记 JOIN 绕过 fail-closed），关联对象先投影 ID，详情/补齐阶段再沿各自资源 Service 读取：

| 资源 | 主表投影的关系 ID | 补齐路径（详情出口） |
| --- | --- | --- |
| material | `unit_id` | `unitService.get`（非租户公共字典） |
| inventory | `material_id` `storage_id` `structure_id` | `materialService`（mapper 开→`getMapperDetail`，关→`get`）、`storageService.get`、`structureService.get` |
| input | `purchase_id` `structure_id` `order_id` `move_id` | `ChannelServices.getPurchaseService().get`、`FactoryServices.getStructureService().get`、`MesServices.getOrderService().getMapperDetail`、`WmsServices.getMoveService().getMapperDetail` |
| output | `sale_id` `move_id` `picking_id` | `ChannelServices.getSaleService().get`、`WmsServices.getMoveService().getMapperDetail`、`MesServices.getPickingService().getMapperDetail` |
| move | `storage_id` | `FactoryServices.getStorageService().get` |
| order | `material_id` `plan_id` `customer_id` | `materialService`（mapper 感知）、`MesServices.getPlanService().getMapperDetail`、`ChannelServices.getCustomerService().get` |
| plan | `customer_id` | `ChannelServices.getCustomerService().get` |
| picking | `structure_id` `order_id` | `FactoryServices.getStructureService().get`、`MesServices.getOrderService().getMapperDetail` |

导出路径**不补齐关系**：导出列只含标量字段（见 §3），关系字段不标 `@Export`，`CollectionUtil.getExportFieldList` 会跳过它们，因此列表导出不会把「只投影了 ID 的关联实体」整对象写进 CSV，也不会逐行触发跨资源权限读取。

## 3. 导出列（`@Export`）与敏感列

`CollectionUtil` 语义：未标 `@Export` 的字段不进 CSV；`TEXT` 原样、`DICTIONARY` 按字段上的 `@Dictionary` 取 label、`NUMBER` 用 `BigDecimal.toPlainString`、空值统一 `-`。

| 资源 | 导出列 | 敏感列（`@SensitiveField`） |
| --- | --- | --- |
| material | name、code、spc（TEXT）；materialType、useType（DICTIONARY）；purchasePrice、salePrice（NUMBER） | purchasePrice、salePrice |
| inventory | quantity（NUMBER）；type（DICTIONARY） | 无 |
| input | billCode（TEXT）；status、type（DICTIONARY） | 无 |
| output | billCode（TEXT）；status、type（DICTIONARY） | 无 |
| move | billCode（TEXT）；status（DICTIONARY） | 无 |
| order | billCode（TEXT）；status、type（DICTIONARY）；quantity、finishQuantity、ngQuantity（NUMBER） | 无 |
| plan | billCode（TEXT）；status、type（DICTIONARY） | 无 |
| picking | billCode（TEXT）；status、type（DICTIONARY） | 无 |

仅 Material 有敏感列，因此只有它的导出会被 `ExportColumnMasker.maskForExport` 实际改写（QUERY 口径、EXPORT 明文授权列保留原值）；其余七资源无 `@SensitiveField`，遮蔽返回原引用（不建副本），但八个 Service 统一保留 `maskForExport` 调用，保证将来给任一资源加敏感列时遮蔽即生效，无需改导出编排。

## 4. 导出取数口径（统一模板）

每个资源 `selectForExport` 复用各自 `XColumns`/`XFilter` + 固定 `id DESC`，无 `LIMIT/OFFSET`；行级权限/租户条件由 MyBatis-Plus 数据权限拦截器按 statement ID 绑定注入，与 page/detail/count/stat 完全同一条链。Service 编排固定五行：shadow 提交 → `selectForExport` → `maskForExport`（请求线程）→ `CollectionUtil.toCsvInputStream` → `ExportHelper.createExportTask`（异步落盘），保留 `fileCode → queryExport` 契约。
