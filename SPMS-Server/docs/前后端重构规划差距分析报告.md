## 3. 接口契约与协同依赖深度分析

### 3.1 已明确的协同点 ✅

| 协同点 | 后端交付 | 前端消费 | 状态 |
|--------|----------|----------|------|
| OpenAPI 3 文档 | SpringDoc + Knife4j | openapi-typescript-codegen | ✅ 已配置 |
| 认证 Token | JWT Access + Refresh | axios 拦截器自动刷新 | ✅ 已实现 |
| 幂等键 | `Idempotency-Key` 校验 | axios 自动生成 UUID | ✅ 已实现 |
| 租户隔离 | `X-Tenant-Id` Header | axios 自动注入 | ✅ 已实现 |
| 行级权限 | `DataPermissionInterceptor` | `x-visibility` 元数据 | ✅ 已设计 |
| 列级脱敏 | `ColumnMaskingAspect` | `x-mask` + `MaskPipe` | ✅ 已设计 |
| 错误码规范 | 统一 `ErrorCode` 枚举 | 统一弹窗/重试逻辑 | ✅ 已设计 |
| 分页/排序/过滤 | `Pageable` + `Specification` | 统一参数名 | ✅ 已设计 |

### 3.2 待细化的协同点 ⚠️

| 协同点 | 现状 | 缺口 | 优先级 | 建议解决方案 |
|--------|------|------|--------|--------------|
| **WebSocket 协议** | airpower-websocket | 前端 `WebSocketManager` 协议未定 | 🔴 高 | 统一采用 **STOMP over WebSocket** 或定义自定义二进制帧协议文档 |
| **SSE/流式响应** | 计划支持 `SseEmitter` | 前端未实现流式消费 | 🟠 中 | 后端提供 `/stream` 端点，前端实现 `EventSource` 消费 |
| **文件断点续传** | 未规划 | 大文件上传需支持 | 🟠 中 | 后端支持分片上传 `/upload/chunk`，前端实现分片上传组件 |
| **推送消息分级** | 未规划 | 前端 `WebSocketManager` 有优先级队列 | 🟠 中 | 后端消息体增加 `priority` 字段，前端按优先级处理 |
| **离线消息持久化** | 未规划 | 前端 `messageQueue` 需后端补发 | 🟠 中 | 后端实现消息 ACK 确认 + 未 ACK 重发机制 |

## 5. 技术债与风险预判

### 5.1 高风险技术债

| 债务项 | 来源 | 影响 | 偿还计划 |
|--------|------|------|----------|
| **@airpower/web 强耦合** | 前端核心依赖 | 升级风险大、定制难 | 第 1 周建立适配器层，长期计划自研核心组件 |

## 7. 结论与判定

### ✅ 可行性判定：**有条件通过，可启动二次开发**

**核心优势**：
- 技术栈选型成熟、团队熟悉度高
- 前后端规划整体一致，接口契约已落地
- 关键基建代码 (API 文档生成、请求网关、权限引擎) 已落地
- 里程碑时间线基本可控，风险可控

### ⚠️ 启动前必须解决的阻塞项

1. **WebSocket 协议统一** (第 1 周三前)
2. **错误码枚举统一** (第 1 周三前)  
3. **联调环境就绪** (第 1 周五前)
4. **ADR 核心决策落笔** (第 1 周五前)

### 📋 建议调整

1. **前端周期延长至 16 周**，与后端对齐，预留 2 周缓冲期
2. **建立每周一次「前后端架构同步会」**，对齐接口变更、阻塞问题
3. **建立「接口变更评审机制」**，任何 Breaking Change 必须评审通过
4. **建立「性能基线对齐机制」**，前后端共同定义 SLA 指标

## 8. 最终建议

> **「可以启动，但必须先解决 4 个 P0 阻塞项，并建立周度同步机制」**
