> 数据来源：`pnpm build` + `pnpm size` 实测（gzip，level 9）。基线为本文档落地前的 895.8/900 KB。

## 二、已实证并落地：去掉 terser `keep_fnames`（-29.7 KB）

### 问题

`vite.config.mts` 的 terser 同时保留了**类名**（`keep_classnames`）和**函数名**（`keep_fnames`），注释写「保留类名以兼容 airpower 反射机制」，但两者被无差别保留。

### 排查

airpower 反射的真实依赖点（`@airpower/web/dist/main.js`）只有 class-transformer 的：

```js
if (!SuperClass || SuperClass.prototype.constructor.name === Transformer.name) { ... }  // 共 4 处
```

即「类名字符串比较」，依赖的是**类名**。项目 `@Type(Entity)` 装饰器全用**类引用**（非字符串）。据此判断：**类名必须保留，函数名对反射无意义**。

### 对照实验（分离两个参数的贡献）

| 配置 | 总体 | 首屏 |
|------|------|------|
| 基线（两者都保留） | 895.8 KB | 414.4 KB |
| 都去掉 | 864.4 KB | 400.0 KB |
| **只去函数名（保留类名）** | **866.1 KB** | **400.5 KB** |
| 只去类名（保留函数名） | 893.7 KB | 413.9 KB |

结论：`keep_fnames` 贡献 ≈ **29.7 KB**，`keep_classnames` 贡献仅 ≈ 2.1 KB。

### 落地

```ts
terserOptions: {
  compress: { keep_classnames: true, keep_fnames: false },
  mangle:   { keep_classnames: true, keep_fnames: false },
}
```

**安全性**：保留 `keep_classnames` ⇒ 类名原样输出 ⇒ `constructor.name === Transformer.name` 比较完全不变 ⇒ class-transformer 反射不受影响。196 单测全绿。

## 三、候选方向（按「收益 × 确定性 / 风险」排序）

### 1. airpower 整包 CSS 按需（49.6 KB → 潜在省 5~15 KB）｜低优先级

- 现状：`src/main.ts:17` 整包 `import '@airpower/web/dist/web.css'`（378 KB 未压缩）。
- 障碍：airpower 只发布**单个** `web.css`，无按组件拆分；项目实际用到了大部分 `.a-*` 组件（50 个分区里仅 `AQrcode` 等极少数未用），可删空间有限。
- 手段：PurgeCSS 删未用选择器 —— 但对 Vue 动态类名（`'a-table-column'`、`:class="item.wrap ? '' : 'nowrap'"`）有误删风险，需人工审计安全名单，维护成本高。
- 建议：**暂缓**。收益小、风险中，不值得现在做。

### 2. echarts（179 KB 懒加载）｜空间已近下限

- 已精准按需，消费者仅 2 处，进一步压缩只能换库（如 uCharts / 自绘 SVG）或去掉 Legend/Tooltip。
- 影响的是 total 而非首屏（懒加载）。
- 建议：**暂不动**。除非 total 再次顶破且无更优选择。

### 3. element-plus（168.8 KB）｜按需已穷尽

- `ElTable/ElDatePicker/ElSelect/ElTree` 等重型组件都是业务必需，无法去。
- 建议：**暂不动**。

### 4. airpower JS（107.3 KB）｜依赖上游

- `@airpower/web` 的 `package.json` `sideEffects` 未声明（非 `false`），Rollup 无法树摇其未用模块（如 MQTT/AI 前端、二维码等）。
- 除非 airpower 上游改为按模块 ESM 导出 + `sideEffects: false`，否则前端侧无解。
- 建议：**记录为上游诉求**，前端不动。

### 5. 首屏 vendor 拆懒加载（潜在省 50~100 KB 首屏）｜中期机会

- 首屏闭包里 element 168.8 + airpower 107.3 = 276 KB，而登录页实际只需其中一小部分（AFrame/ADialog + ElButton/ElInput/ElForm）。
- 若把 `ATable/ElTable/ElDatePicker/ElSelect/ElTree` 等「管理页重组件」拆到懒加载 chunk，首屏可显著下降。
- 障碍：airpower 是单体 dist，`ATable` 与 `ADialog` 同在一个文件，无法按组件懒加载；element 侧可按需拆，但会引入 chunk 碎片化与「公共依赖重复」风险。
- 建议：**首屏当前 400.5/450 未超预算（余 49.5 KB）**，等首屏逼近红线再启动。

## 四、落地顺序建议

1. ✅ **keep_fnames**（已落地）：-29.7 KB，总体 895.8 → 866.1，腾出约 34 KB（≈3 个模块页）。
2. 保持 `pnpm size` 门禁观测：总体在 880 KB 打预警，不等到 900 顶破再决策。
3. 真正需要再压缩时，按「风险从低到高」依次评估：airpower CSS 按需 → 首屏 vendor 拆懒加载 → echarts 换库。

## 五、口径提醒（不临时改数）

`check-bundle-size.mjs` 头部已写明：首屏预算 450 KB 是红线（影响真实加载体验）；total 900 KB 是退化预警（含全部懒加载分包，管理端每加一页 +5~15 KB 是预期增长）。本次 keep_fnames 是「压缩」而非「加预算」，符合脚本口径。
