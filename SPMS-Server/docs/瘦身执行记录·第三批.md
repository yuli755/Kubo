## 一、为什么这次要动 WMS（本批唯一有业务语义的一刀）

MES 不是独立挂件，它把生产单据挂进了 WMS 的核心单据：

| 咬点 | 原状 | 处理后 |
| --- | --- | --- |
| `wms.input` 入库类型 | `PRODUCTION(4, 生产入库)` + `InputEntity.order` 关联生产订单，完成时回写订单状态 | 类型与关联删除，保留 普通/转移/采购入库 |
| `wms.output` 出库类型 | `PICKING(4, 领料出库)` + `OutputEntity.picking` 关联领料单，出库明细会回写领料数量 | 类型与关联删除，保留 普通/转移/销售出库 |
| `factory.structure` | `operationList`（可执行工序，多对多） | 字段与编辑器 UI 删除（产线/工位保留） |
| 业务概况看板 | 14 个资源（含 mes.order/plan/picking） | **11 个资源** |
| 编号规则 | 生产计划号/生产订单号/领料单号/工序编码/配方编码/工艺编码 | 6 条删除 |

**结论**：仓储单据不再有「生产」语义，入库=采购/转移/普通，出库=销售/转移/普通。这是有意的语义收窄，
不是误删——若将来要接生产，应按新域模型重建，而不是在 WMS 里留一个悬空的 `orderId` 字段。
