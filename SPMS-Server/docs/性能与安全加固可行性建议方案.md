# 性能与安全加固可行性建议方案（2026-09-10）

> 触发背景：CI 因账单额度阻塞无法跑三 job；前端视觉改造（V1–V8）已全部落地。趁等待额度恢复，
> 对「性能」与「安全」做一轮**基于代码事实**的可行性评估与修复。
> 本文给出诚实基线 + 已发现的具体问题 + 分项清单 + 推荐执行顺序，每项标注价值/工作量/风险/前置。
> 与既有文档不冲突：不动数据权限/脱敏/审计的判定逻辑，`maskContract` 门禁守住这条边界。

---

## 0. 结论先行（TL;DR）

1. **安全侧的收获比性能侧更实、更快**：本轮静态扫描 + `pnpm audit` 直接定位到 6 处具体问题
   （见 §1），其中「前端 29 个依赖漏洞」「硬编码密钥/弱凭据」是**确定性、可立即修**的，
   不依赖 CI 也能落地并本地验证。

2. **性能侧的主矛盾不在代码、在包体积**：体积预算已用 889/900 KB（>98%），且已预警
   「下一个模块页就会顶破」。这不是本次改造引入的（改造前就在 887 KB 高位），根因是
   ECharts（~620KB）/ vendor-element（~595KB）/ vendor-airpower（~314KB）三大 chunk。
   优化方向是**懒加载与分包**，不是微调代码。

3. **推荐执行顺序**：`S1 依赖漏洞` → `S2 硬编码密钥外置` → `S3 生产配置加固` →
   `P1 包体积/懒加载` → `P2 后端查询与缓存` → `S4 安全响应头/CSP`（S4 需 CI 回归，额度恢复后做）。

## 2. 分项方案与修复

### S1 · 前端依赖漏洞（axios 升级）【高价值 · 已落地】

- **现状**：`axios 1.13.2` 命中 29 个 advisory（含 high：凭据窃取、响应走私、空字节注入等）。
- **方案**：升级到 `1.20.0`（同 1.x，向后兼容）；`@airpower/web` 传递的 axios 由 pnpm 去重到同版本。
- **价值**：高（消除全部 29 个漏洞）；**工作量**：低；**风险**：低（1.x 内升级 + 本地全量回归）。

### S2 · 硬编码密钥外置【高价值 · 已落地】

- **现状**：JWT 密钥 `1234567890`、InfluxDB 令牌明文进库。
- **方案**：
  - JWT 密钥改为环境变量占位 `${AIRPOWER_API_ACCESS_TOKEN_SECRET:...}`，保留 dev 默认值、生产由部署注入；
  - `InfluxConfig` 令牌默认值清空，改为从配置/环境变量注入（`app.influxdb.token`），代码里不再含真实令牌。
- **价值**：高（密钥不再进 git）；**工作量**：低；**风险**：低（dev 默认值不变）。

### S3 · 生产配置加固【中-高价值 · 已落地】

- **现状**：生产 `api-docs.enabled: true`、`useSSL=false`、凭据 `kubo/kubo` 进库。
- **方案**：
  - `springdoc.api-docs.enabled: false`（生产不暴露 OpenAPI schema）；
  - 凭据改 `${DB_USERNAME:...}` / `${DB_PASSWORD:...}` 环境变量占位；
  - JDBC `useSSL=false` → 标注「内网环境默认、公网部署必须开启」（值本身由部署拓扑决定，代码只留正确注释）。
- **价值**：中-高；**工作量**：低；**风险**：低（占位符默认值保持原值，本地/CI 不破）。

### S4 · 安全响应头 / CSP【中价值 · 分两阶段】

- **第一批（后端零风险头）已落地**：`SecurityHeadersFilter` 注入
  `X-Content-Type-Options: nosniff` / `Referrer-Policy` / `X-XSS-Protection: 0` / `Permissions-Policy`，
  刻意不含 CSP（前端由 nginx 托管、后端不托管静态资源，CSP 加在后端会误伤内联脚本/ECharts/WebSocket）。
- **第三批（前端 nginx 层）已落地 Report-Only**：`nginx.conf` 前端 `location /` 补齐安全头 +
  `X-Frame-Options: DENY`（防点击劫持，后端只出 JSON 加不了）+ CSP **Report-Only** 起步：
  - `script-src 'self' 'sha256-…'`（hash 精确放行 index.html 内联防闪烁脚本，无需 `unsafe-inline`）；
  - `style-src 'self' 'unsafe-inline'`（Vue 动态 `:style` + Element Plus 运行时内联样式，必须保留）；
  - `connect-src 'self' ws: wss:`（同源 API + WebSocket）、`worker-src`（PWA）、`object-src 'none'`、
    `frame-ancestors 'none'`、`base-uri 'self'`、`form-action 'self'`；
  - 顺手关闭 `autoindex`（目录列表暴露静态结构，攻击面测绘来源）；
  - 新增 `cspContract.spec.ts` 门禁：锁 CSP 头存在、hash 与 index.html 一致、script-src 无
    `unsafe-inline`、有 X-Frame-Options、无 autoindex on。
- **强制化（移除 `-Report-Only`）仍待 CI 额度恢复**：Report-Only 不阻断任何加载、零白屏风险，
  可先行上线观察 console 违规；把 `-Report-Only` 去掉转强制 CSP 需要真实环境回归（确认无遗漏的
  内联资源被阻断），这是本批唯一留给 CI 的尾巴。
- **第六批（2026-09-10）：强制化前静态完整性审查**，发现并修复一处**真实遗漏**——
  `axios.download()` 用 `<a download href=blob:>` 导出文件，Firefox 把这种 blob 导航视为 frame 导航、
  受 `frame-src`（fallback 到 `default-src 'self'`）控制；原 CSP 无 `frame-src`，直接强制化会让
  **Firefox 用户无法下载导出文件**。已补 `frame-src 'self' blob:`，并在 `cspContract` 加门禁锁住。
  这印证了「强制化必须真实回归」不是过度谨慎。

#### S4 强制化 SOP（代码已转正，待本机/真实环境回归）

- **代码已转正（2026-09-10）**：`nginx.conf` 的 CSP 已从 `Content-Security-Policy-Report-Only`
  改为强制 `Content-Security-Policy`（指令值不变），`cspContract.spec.ts` 门禁同步改为锁「强制模式」
  （出现 Report-Only 即失败）。因沙箱无浏览器/nginx 二进制，无法运行时回归，故**代码先行、回归待办**。
- **待办（本机/CI 任一方）**：
  1. `docker compose up` 后按 nginx.conf 注释里的**回归清单**逐项点验（登录首屏 / 深色切换 /
     ECharts 图表页 / 文件导出 **Firefox+Chrome 各一次** / WebSocket 推送 / PWA 离线 / 图片字体）；
  2. 任一白屏/失效：把 `Content-Security-Policy` 改回 `Content-Security-Policy-Report-Only` 即回滚，
     浏览器 console 会列出被阻断的资源，据此补指令。
- **回滚**：只改 nginx.conf 一个词，无需改代码；回滚后 `cspContract.spec.ts` 会红（提示"仍是
  Report-Only"），这是预期的——修复后再转正即可。

### P1 · 包体积与懒加载【中价值 · 持续项】

- **现状**：ECharts 已按需注册 + 动态 import（懒加载），但 vendor-element / vendor-airpower 仍在主包。
- **方案**：评估进一步 manualChunks 切分、`@airpower/web` 按子路径引入、大组件（设备监控等）懒加载。
- **价值**：中；**工作量**：中；**风险**：中（分包需逐页回归）。

### P2 · 后端查询与缓存【低优先级 · 已梳理（2026-09-10）】

- **缓存命中点（已盘点，配置合理，无需改动）**：
  - `RedisCacheConfig`：Spring Cache + Redis，全局 TTL 30 分钟，JSON 序列化，`disableCachingNullValues`；
  - `DataFieldPolicyService`：`@Cacheable("datapermission:field-policies")` 三档 key
    （`resourceKey:fieldName:roleCode` / `list:resourceKey:actionName` / `all:resourceKey`），
    写侧 `@CacheEvict(allEntries=true)` 两处，失效点齐全；
  - `JpaPermissionRuleProvider`：`@Cacheable("datapermission:resource")` / `("datapermission:policies")`，
    `@CacheEvict` 三处（单 key / 单 cache / 双 cache allEntries）。
  - 结论：缓存都集中在**数据权限模块**（每请求必查的权限规则 / 脱敏策略），是真正热点，命中合理。
- **N+1 面（已评估，不重构）**：全仓 73 处 JPA 关系注解、无 `@EntityGraph`/`fetch join`；但读侧热点
  （列表 / 详情 / 导出 / 统计）已全部下沉到 `KuboBaseMapper` 子接口 + 显式 XML（21 个，`resources/mapper`），
  列表路径无 N+1。详情页 `getMapperDetail` 沿 JPA 补齐关系，理论上存在二次查询，但属读侧换轨的既定设计，
  且逐页回归成本高 —— 按「零风险梳理」口径**只记录、不动**。

| 第二批 | S4 安全响应头（零风险头）+ P1 包体积评估 | 否（本地可验证） | **已落地（2026-09-10，见 §3.1）** |

| 第四批 | P2 后端缓存梳理 + P3 生产包体日志关闭 | 否 | **已落地（2026-09-10，见 §3.2）** |

### 3.1 第二批落地说明（S4 零风险头 + P1 评估）

**S4（第一批：零风险头）已落地**：新增 `SecurityHeadersFilter`，注入
`X-Content-Type-Options: nosniff` / `Referrer-Policy: strict-origin-when-cross-origin` /
`X-XSS-Protection: 0` / `Permissions-Policy`（禁摄像头/麦克风/定位/支付）。
**刻意不含 CSP**：CSP 涉及前端内联脚本（index.html 防闪烁脚本）、ECharts dataURI 与 WebSocket，
加在后端会白屏，且后端 `add-mappings=false` 不托管静态资源——CSP 应在前端托管层（Nginx）收紧，
留待第三批（CI 恢复 + 真实环境回归）。已加 `maskContract` 反向门禁：后端 filter 一旦出现 CSP 即失败。

**P1（包体积）结论：优化已到位，不做强行拆分**。实测首屏 414.1/450 KB（健康，36KB 余量）、
总体 894.2/900 KB（>98% 预警）。`check-bundle-size.mjs` 头注释已写明：`total` 含全部懒加载分包，
本质是「共享层变大的退化预警」而非加载性能指标；每加一个模块页 +5~15KB 是预期内正常增长。
当前 vendor 已分 5 片（echarts/vue/element/query/airpower）、echarts 已按需注册 + 懒加载、
element-plus 已走 aggregate+shim 树摇、airpower CSS 为第三方全量（无可拆子路径）。首屏才是真正
影响用户的指标，它健康。vendor 进一步拆分收益低、且 CI 无法回归风险高，故延后至额度恢复后。

### 3.2 第四批落地说明（P2 缓存梳理 + P3 生产日志关闭）

**P3（生产包体日志泄露）已修复**：airpower 的 `airpower.api.request-log` / `response-log` 是
「请求/响应**包体**日志」开关（框架源码 `ApiConfig` 默认 `true`，注释明写"输出请求/响应包体日志"）。
原 `application-production.yml` 未覆盖，生产继承 `true` 会把登录密码、token、客户 PII、查询结果
明文打进日志。已在生产配置显式 `request-log: false` / `response-log: false`（排障改用 airpower 默认的
`bodyTraceId`，响应体带 traceId 可关联日志），并在 `maskContract` 加门禁：生产配置两开关必须是 `false`。

**P2（后端查询与缓存）已梳理，无需重构**：缓存命中点集中在数据权限模块（field-policies / resource /
policies 三个 cache，TTL 30 分钟，失效点齐全）；读侧热点已下沉 Mapper 显式 SQL（21 个 XML），列表路径
无 N+1。详情页 JPA 关系补齐的理论二次查询属既定设计，按零风险口径只记录不动。
