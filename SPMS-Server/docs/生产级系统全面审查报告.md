## 0. 结论先行

项目的**工程基础设施成熟度很高**：CI 三 job（web/server/migrations）+ 10+ 门禁 + 防空转防护、
读侧换轨、数据权限 outbox、脱敏契约、DDL 受控变更、H2/MySQL 方言双轨验证——这些在同类项目里
少见，是「可持续运行」的坚实底子。本会话已累计落地 S1–S6 / P1–P3 与前端 CSP（nginx Report-Only）。

剩余差距集中在**「最后一公里」的生产化细节**，多为配置级、零风险、可本地验证，按优先级：

| 级别 | 项 | 一句话 |

## 1. 安全（已大幅收敛，余少量运维项）

本会话已落地：依赖漏洞 29→0、JWT/Influx 密钥外置、生产凭据外置、生产关 API 文档、
后端安全响应头、前端 nginx 安全头 + CSP Report-Only + 关目录列表、生产关包体日志。
剩余：

- **CSP 强制化（P3）**：现为 `Content-Security-Policy-Report-Only`（不阻断，零白屏风险）。
  观察期确认 console 无违规后，移除 `-Report-Only` 转强制 —— 需 CI + 真实环境回归。
  见《性能与安全加固可行性建议方案》S4。
- **X-Request-Time 是观测预留、非防重放**（已诚实化注释）：真正的防重放需后端加时间窗口校验，
  属功能开发，暂缓。
- **`application.yml` 基础凭据 root/root + useSSL=false**：仅 local 默认值，生产已用
  `${DB_USERNAME}/${DB_PASSWORD}` 覆盖；公网部署须 `useSSL=true`（S3 注释已写明）。

## 2. 性能（体积已健康，余配置级）

- 体积预算：首屏 414/450 KB（健康）、总体 894/900 KB（懒加载正常增长，口径已写明）。
- vendor 5 分片、echarts 按需+懒加载、element-plus aggregate+shim 树摇、airpower 全量无可拆。
- 后端缓存命中点集中在数据权限模块（TTL 30m、失效点齐全）；读侧热点已下沉 Mapper 显式 SQL。

## 7. 部署运维（本轮 P0）

- **P0：根 `Dockerfile` 用 yarn，仓库只有 `pnpm-lock.yaml`**。
  - 现状：`yarn install --ignore-engines` 无锁文件 → 依赖解析与 CI(pnpm) 不一致；
    `pnpm.overrides`（axios 1.20.0 漏洞锁定）对 yarn 不生效 → 镜像可能打出带漏洞的 axios。
  - 修复：Dockerfile 改 pnpm（corepack）+ `pnpm install --frozen-lockfile` + `pnpm build`。
- **SPMS-Server Dockerfile `-DskipTests`**：可接受（CI 已测），保留。

## 8. 前端质量

- 路由守卫（认证→权限）、axios 统一响应/错误处理、401 刷新重试、PWA 离线、主题三态、骨架屏、
  reduced-motion 降级 —— 均较完善。

## 附 · PWA 离线缓存泄露面（第二十七批，✅ 2026-09-11）

`vite.config.mts` 的 VitePWA 原配置对 `/api/` 做 `NetworkFirst` runtimeCaching（Cache Storage 缓存
5 分钟）：API 响应是「按当前用户租户 + 行级/列级权限过滤后的业务数据」，落进浏览器缓存后，在共享
浏览器上会把上一个用户的可见数据在离线兜底时喂给下一个用户——跨租户泄露面。修复：移除 `/api/`
运行时缓存（生产 `sw.js` 已确认无 `NetworkFirst`/`kubo-api-cache`），PWA 离线价值只保留静态壳
（js/css/html 预缓存），动态数据一律走网络不落缓存。
