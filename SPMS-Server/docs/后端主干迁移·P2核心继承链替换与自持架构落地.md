## 一、架构替换概览与核心基类脱离

在 Phase 1 完成请求 DTO、响应协议、业务异常、权限元数据接管之后，Phase 2 将 Spring Boot + JPA + MyBatis-Plus 的主干骨架从旧框架中彻底解耦并自持：

```
                    ┌─────────────────────────┐
                    │    ApiController        │ (Spring MVC Controller)
                    └────────────┬────────────┘
                                 │ extends
                    ┌────────────┴────────────┐
                    │     BaseController      │ ── implements ──► CurdAction (自持验证分组)
                    └────────────┬────────────┘
                                 │ injects
                    ┌────────────▼────────────┐
                    │       BaseService       │
                    └──────┬───────────┬──────┘
             injects (JPA) │           │ injects (MyBatis-Plus)
                    ┌──────▼─────┐ ┌───▼───────────┐
                    │  BaseRepo  │ │ StorageMapper │ (可选读侧加速)
                    └──────┬─────┘ └───┬───────────┘
                           │           │
                    ┌──────▼───────────▼──────┐
                    │       BaseEntity        │ (JPA MappedSuperclass)
                    └─────────────────────────┘
```

### 1. 实体根类：`BaseEntity`（彻底解耦 `CurdEntity`）
- 继承并标记为 JPA `@MappedSuperclass`，拥有自持的 `id`, `isDeleted`, `remark`, `createTime`, `updateTime`。
- 实现自持的标记接口与克隆/反射机制，不再继承 `cn.hamm.airpower.curd.base.CurdEntity`。
- 所有应用实体（`UserEntity`, `DepartmentEntity`, `StorageEntity` 等）继承自持 `BaseEntity`。

### 2. 仓储底座：`BaseRepository`（彻底解耦 `ICurdRepository`）
- 定义为 Spring Data JPA 核心接口：
  `public interface BaseRepository<E extends BaseEntity> extends JpaRepository<E, Long>, JpaSpecificationExecutor<E>`
- 自持统一的软删除、按 ID 查活跃记录、租户隔离过滤等 Specification 辅助方法，不再继承 `cn.hamm.airpower.curd.base.ICurdRepository`。

### 3. 服务引擎：`BaseService`（彻底解耦 `CurdService`）
- 拥有自持的单表与关联 CRUD 引擎：
  - `getDetail(Long id)`：带软删除过滤与关联装配；
  - `add(E entity)`：前置校验、默认字段注入、数据入库、后置 hook；
  - `update(E entity)`：字段级安全更新、不可更新字段保护、后置 hook；
  - `delete(Long id)`：级联/外键探针校验、树形阻断校验、软删除；
  - `getPage(QueryPageRequest<E> request)`：JPA Specification 动态条件组装 + 分页计算，支持读侧 MyBatis-Plus 扩展。
- 读侧分页响应采用自持的 `ReadPage.Counts` 计算及 `QueryPageResponse` 结构装配，保持行与排序引用。
- 不再继承 `cn.hamm.airpower.curd.base.CurdService`。

### 4. 表现层控制器：`BaseController`（彻底解耦 `CurdController`）
- 继承 `ApiController`，实现自持 `CurdAction` 动作分组接口（包含 `WhenGetDetail`, `WhenAdd`, `WhenUpdate`, `WhenDelete`, `WhenGetPage`, `WhenGetList` 等 JSR-303/380 校验分组）。
- 全量端点方法签名直接返回自持 `ApiResponse<T>`：
  - `ApiResponse<E> getDetail(@RequestBody E entity)`
  - `ApiResponse<E> add(@RequestBody @Validated(CurdAction.WhenAdd.class) E entity)`
  - `ApiResponse<E> update(@RequestBody @Validated(CurdAction.WhenUpdate.class) E entity)`
  - `ApiResponse<Void> delete(@RequestBody E entity)`
  - `ApiResponse<QueryPageResponse<E>> getPage(@RequestBody QueryPageRequest<E> request)`
  - `ApiResponse<List<E>> getList(@RequestBody QueryListRequest<E> request)`
  - `ApiResponse<Void> publish(@RequestBody E entity)`
- 子类业务控制器无需返回旧 `Json`，直接以类型安全的 `ApiResponse` 与前端通信。
- 不再继承 `cn.hamm.airpower.curd.base.CurdController`。

### 5. 请求拦截与链路追踪：`RequestInterceptor`（彻底解耦 `CurdRequestInterceptor`）
- 直接实现 Spring MVC `HandlerInterceptor` 接口：
  - 自持 `preHandle`, `postHandle`, `afterCompletion` 完整生命周期；
  - 读取请求头 `X-Trace-ID` 并结合自持 `cn.hamm.spms.framework.util.Tracer`（ThreadLocal + MDC 兜底）管理分布式链路跟踪标识；
  - 拦截器在响应头自动回填 `X-Trace-ID`，完成请求上下文清理，无内存泄漏隐患；
  - 继承自持 `PermissionScanner` 与 `AccessTokenFacade` 进行令牌鉴权与权限树匹配，彻底告别旧权限与旧拦截基类。
- 不再继承 `cn.hamm.airpower.curd.interceptor.CurdRequestInterceptor`。

## 二、退场符号与防回潮加固

本次重构中，以下 5 大基类与接口被正式移入永久退场清单，并受 `infra/scripts/check-airpower-backend.mjs` 门禁与 CI 的严格拦截，任何重新引入都将导致构建熔断：

1. `cn.hamm.airpower.curd.base.CurdEntity`
2. `cn.hamm.airpower.curd.base.ICurdRepository`
3. `cn.hamm.airpower.curd.base.CurdService`
4. `cn.hamm.airpower.curd.base.CurdController`
5. `cn.hamm.airpower.curd.interceptor.CurdRequestInterceptor`

加上此前阶段已退场的 14 个核心工具类/接口（`CollectionUtil`, `ReflectUtil`, `DateTimeUtil`, `DictionaryUtil`, `FileUtil`, `NumberUtil`, `RandomUtil`, `StringUtil`, `TraceUtil`, `TreeUtil`, `TaskUtil`, `ITree`, `IException`, `Phone`）以及 `PermissionUtil`, `IPermission`，累计永久退场符号已达 **21 个**。

同时，`DepartmentController` 与 `MenuController` 重构为自持 `ApiResponse`，全仓零 Json 控制器增至 12 个。
