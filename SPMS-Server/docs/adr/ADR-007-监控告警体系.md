# ADR-007: 监控告警体系选型 - Prometheus + Grafana + SkyWalking + ELK/Loki

> **状态**：✅ 已通过
> **日期**：2026-08-01
> **决策者**：DevOps + 架构师
> **技术栈影响**：可观测性体系
> **关联文档**：[可观测性架构](../archive/Kubo 平台高并发重构实施路线规划计划.md#可观测三支柱全覆盖)

---

## 1. 背景与问题

### 问题描述
- 微服务架构需要全链路可观测性：Metrics、Tracing、Logging
- 原系统无统一监控体系，故障发现依赖用户反馈
- 需要支撑 10k+ 并发、7×24 小时生产环境

### 约束条件
- 团队对 Prometheus/Grafana 有经验
- 预算有限，倾向开源方案
- 需要支持多语言 (Java/Go/Node.js) 埋点
- 需要支持 Kubernetes 原生集成

### 驱动因素
- 故障快速发现与定位 (MTTD < 5min, MTTR < 30min)
- 性能基线建立与回归检测
- 容量规划与自动扩缩容决策支持

---

## 2. 备选方案

### 方案 A: Prometheus + Grafana + SkyWalking + ELK/Loki ✅ **选中**

| 维度 | 评价 |
|------|------|
| **优点** | - **三支柱全覆盖**：Metrics (Prometheus) + Tracing (SkyWalking) + Logging (ELK/Loki)<br>- **开源免费**、社区活跃、生态完善<br>- **Kubernetes 原生集成**：ServiceMonitor、PodMonitor、Operator 模式<br>- **SkyWalking**：Java 无侵入探针、自动化埋点、服务拓扑、数据库/缓存/MQ 调用链路<br>- **Grafana**：统一可视化、告警引擎、多租户、插件生态丰富<br>- **Loki**：日志聚合轻量、Label-based 索引、与 Prometheus 标签体系一致<br>- **成本可控**：开源免费、资源占用可控 |
| **缺点** | - 组件多 (Prometheus/Alertmanager/Grafana/SkyWalking OAP/ES/Loki/Promtail)<br>- 运维复杂度中等<br>- SkyWalking OAP 存储压力大 (需 ES/ClickHouse)<br>- 告警规则调优需要经验 |
| **技术成熟度** | 高 |
| **团队熟悉度** | 中高 |
| **运维复杂度** | 中 |
| **成本** | 低 (开源) |
| **扩展性** | 强 |

### 方案 B: 商业 APM (Datadog / New Relic / Dynatrace)

| 维度 | 评价 |
|------|------|
| **优点** | - 开箱即用、零运维<br>- 功能最全、AI 异常检测、智能根因分析<br>- 统一平台、无需自建组件<br>SLA 保障、专业支持 |
| **缺点** | - **成本极高** (按主机/APM 宿主计费，年费数十万起)<br>- 数据上云、合规风险<br>- 定制化能力弱、锁定厂商<br>- 国内网络访问不稳定 |
| **技术成熟度** | 高 |
| **团队熟悉度** | 低 |
| **运维复杂度** | 低 (SaaS) |
| **成本** | 极高 |

### 方案 C: Prometheus + Grafana + Jaeger + ELK

| 维度 | 评价 |
|------|------|
| **优点** | - Jaeger 纯分布式追踪、CNCF 毕业项目<br>- 组件相对轻量 |
| **缺点** | - Jaeger 无 Java 无侵入探针 (需手动埋点/OpenTelemetry SDK)<br>- 无服务拓扑、无拓扑分析<br>- 无指标聚合、无告警引擎 (需配合其他) |
| **技术成熟度** | 高 |
| **团队熟悉度** | 低 |
| **运维复杂度** | 中 |
| **成本** | 低 |

### 方案 D: OpenTelemetry + 自建后端 (VictoriaMetrics + Tempo + Loki)

| 维度 | 评价 |
|------|------|
| **优点** | - OpenTelemetry 统一标准、厂商中立<br>- VictoriaMetrics 高性能、PromQL 兼容、压缩率高<br>- Tempo 纯对象存储、成本低<br>- 统一 OTel Collector 采集 |
| **缺点** | - 组件较新、生态不如 Prometheus/SkyWalking 成熟<br>- 团队零经验、学习曲线陡峭<br>- VictoriaMetrics 单节点写入瓶颈 (需集群版)<br>- Tempo 查询性能依赖对象存储 |
| **技术成熟度** | 中 |
| **团队熟悉度** | 低 |
| **运维复杂度** | 中 |
| **成本** | 低 |

## 3. 决策结果

**最终选择**：方案 A - **Prometheus + Grafana + SkyWalking + ELK/Loki**

### 组件选型矩阵

| 可观测支柱 | 组件 | 版本 | 部署模式 | 关键配置 |
|-----------|------|------|----------|----------|
| **Metrics** | Prometheus | 2.48+ | K8s Operator (kube-prometheus-stack) | 15d 保留、2 副本、远程写入 VictoriaMetrics (可选) |
| **Metrics 存储** | VictoriaMetrics (可选) | 1.98+ | 单节点/集群 | 1 年保留、压缩率 10x |
| **Metrics 可视化/告警** | Grafana | 10.2+ | K8s Deployment | 统一仪表板、统一告警引擎、多租户 |
| **Tracing** | SkyWalking | 9.7+ | K8s Deployment (OAP + UI) | SkyWalking Java Agent 无侵入探针 |
| **Tracing 存储** | Elasticsearch | 8.11+ | K8s StatefulSet (3节点) | 7 天热 + 30 天冷、ILM 策略 |
| **Logging** | Loki | 2.9+ | K8s Deployment (单节点/集群) | 30 天保留、Label-based 索引 |
| **Log 采集** | Promtail | 2.9+ | K8s DaemonSet | 自动发现 Pod 标签、多行日志合并 |
| **Log 搜索/可视化** | Grafana (LogQL) | 10.2+ | 同 Grafana | 统一查询界面 |

### 3.2 Prometheus 关键采集规则

```yaml
# prometheus.yml 关键规则
scrape_configs:
  - job_name: kubernetes-pods
    kubernetes_sd_configs:
      - role: pod
    relabel_configs:
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
        action: keep
        regex: true
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_path]
        action: replace
        target_label: __metrics_path__
        regex: (.+)
      - source_labels: [__address__, __meta_kubernetes_pod_annotation_prometheus_io_port]
        action: replace
        regex: ([^:]+)(?::\d+)?;(\d+)
        replacement: $1:$2
        target_label: __address__
      - action: labelmap
        regex: __meta_kubernetes_pod_label_(.+)

  - job_name: spring-boot-actuator
    metrics_path: /actuator/prometheus
    kubernetes_sd_configs:
      - role: pod
    relabel_configs:
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
        action: keep
        regex: true
```

### 3.3 核心告警规则 (PrometheusRule)

```yaml
# 核心告警规则示例
groups:
  - name: kubo-platform-critical
    interval: 30s
    rules:
      # 实例级
      - alert: InstanceDown
        expr: up{job=~"kubernetes-pods"} == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: '实例 {{ $labels.pod }} 停止运行'
          description: '{{ $labels.pod }} 在 {{ $labels.namespace }} 命名空间下已停止超过 1 分钟'

      # JVM 级
      - alert: JVMMemoryHigh
        expr: (jvm_memory_used_bytes{area="heap"} / jvm_memory_max_bytes{area="heap"}) > 0.85
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: JVM 堆内存使用率过高
          description: '{{ $labels.pod }} 堆内存使用率 {{ $value | humanizePercentage }}'

      - alert: JVMGCPressure
        expr: rate(jvm_gc_pause_seconds_sum[5m]) / rate(jvm_gc_pause_seconds_count[5m]) > 0.1
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: JVM GC 压力过大
          description: '{{ $labels.pod }} 平均 GC 暂停时间过长'

      # 业务级
      - alert: APIHighErrorRate
        expr: sum(rate(http_server_requests_seconds_count{status=~"5.."}[1m])) by (service) / sum(rate(http_server_requests_seconds_count[1m])) by (service) > 0.05
        for: 2m
        labels:
          severity: critical
        annotations:
          summary: '{{ $labels.service }} 错误率超过 5%'

      - alert: APIHighLatency
        expr: histogram_quantile(0.99, sum(rate(http_server_requests_seconds_bucket[5m])) by (le, service)) > 2
        for: 3m
        labels:
          severity: warning
        annotations:
          summary: '{{ $labels.service }} P99 延迟超过 2s'

      # MQ 级
      - alert: RabbitMQQueueBacklog
        expr: rabbitmq_queue_messages_ready > 10000
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: 'RabbitMQ 队列 {{ $labels.queue }} 堆积 {{ $value }} 条消息'

      # 数据库级
      - alert: MySQLConnectionsHigh
        expr: mysql_global_status_threads_connected / mysql_global_variables_max_connections > 0.8
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: 'MySQL 连接数使用率超过 80%'

      # 缓存级
      - alert: RedisMemoryHigh
        expr: redis_memory_used_bytes / redis_memory_max_bytes > 0.85
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: 'Redis 内存使用率超过 85%'

      # WebSocket
      - alert: WebSocketReconnectStorm
        expr: rate(ws_reconnect_total[5m]) > 20
        for: 2m
        labels:
          severity: critical
        annotations:
          summary: WebSocket 重连风暴，每分钟重连超过 20 次
```

### 3.4 Grafana 仪表板标准化

| 仪表板类别 | 关键面板 | 刷新间隔 |
|-----------|----------|----------|
| **集群概览** | 集群健康度、Pod 状态、资源使用率、网络 I/O | 30s |
| **JVM 专题** | 堆/非堆内存、GC 频率/耗时、线程池、类加载 | 30s |
| **业务 API** | QPS、P50/P95/P99 延迟、错误率、吞吐量 | 30s |
| **JVM GC 专题** | GC 原因分布、停顿时间分布、内存碎片 | 1m |
| **数据库** | 连接数、QPS、慢查询、复制延迟、锁等待 | 30s |
| **Redis** | 内存、命中率、命令耗时、连接数、键空间 | 30s |
| **RabbitMQ** | 队列堆积、吞吐量、消费延迟、连接数 | 30s |
| **SkyWalking 拓扑** | 服务拓扑、调用链路、错误率热力图 | 1m |
| **业务大盘** | 订单量、库存周转、工单完成率、设备在线率 | 5m |
